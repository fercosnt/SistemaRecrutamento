# Auditoria de Navegação & Arquitetura de Informação — 2026-06-28

Read-only. Disparada pelo achado `ENTREV-PERFIL-DUP-01`, que revelou um padrão sistêmico.
Escopo: todas as ~40 rotas do router, as duas personas (Candidato e RH/Admin), e o
grafo real de quem-navega-para-quê (`navigate()` / `<Link>` / sidebar).

---

## TL;DR — Veredito

**A navegação de produção está estruturalmente incompleta.** A maior parte do funil
construído no M2 (avaliação do candidato + workspaces RH de entrevista/decisão/redação)
**não tem porta de entrada na navegação real** — só é alcançável por URL direta ou pelo
menu de desenvolvimento. As features funcionam (provamos no UAT), mas o usuário comum
não chega até elas clicando.

**Causa-raiz:** um `DevNavigationMenu` (DEV-only) mascarou o problema durante todo o
desenvolvimento e os testes.

Severidade real: **ALTA** (de produto). Não é bug de código — é wiring de navegação +
limpeza de legado. Mas sem isso, o M2 RH é inoperável por um usuário real.

---

## 1. Achado-raiz — o menu de navegação é DEV-only

`src/App.tsx:222` → `{import.meta.env.DEV && <DevNavigationMenu />}`
Comentário literal no código (App.tsx:128): *"Menu de desenvolvimento • Remover em produção"*.

É o botão flutuante azul (hambúrguer) que aparece em **todos os prints** do UAT. Ele dá
acesso a qualquer rota — então em DEV tudo parece navegável. **Em produção ele some**, e
sobra só a navegação real (sidebar RH + links dentro das páginas + `navigate` programático).
Conclusão: a navegação de produção nunca foi exercitada de ponta a ponta.

## 2. O que É alcançável na navegação real (produção)

- **Público:** Landing `/` → `/vagas` → `/vagas/:id` → `/cadastro` → `/auth/login` ✅
- **Candidato:** login → `/candidato/dashboard` → **só leva a `/vagas`**. Há `/candidato/perfil` (real). Candidatura: `/vagas/:id` → `/candidato/candidatura/formulario/:slug` ✅

## 5. Jornadas E2E — onde quebram (em produção)

- **Candidato pós-candidatura → avaliação assíncrona:** ❌ QUEBRA. O dashboard só leva a
  `/vagas`; nem dashboard nem perfil linkam para `/candidato/avaliacao/:id`. O candidato
  não tem como retomar/abrir a avaliação pela navegação.
- **RH triando → avaliar no funil:** ❌ QUEBRA no meio. Da TriagemTable o RH vai para o
  **perfil mock**, não para os workspaces reais (entrevista/decisão/redação). O funil RH
  do M2 não tem entrada.
- **Candidato → explicação LGPD:** ❌ sem entrada na UI (esperado via notificação, mas não existe).
- **Admin → telas de IA/custo/viés:** ❌ sem entrada.

## 6. Recomendações (priorizadas)

1. **[ALTA] Cabear o funil — candidato + RH** (expande o `RH-NAV-WIRING-01`):
   - RH: da TriagemTable/perfil real → entrada para os 3 workspaces, idealmente **por etapa
     da candidatura** (entrevista/decisão/redação aparecem conforme `etapa_atual`).
   - Candidato: dashboard/perfil → entrada para a avaliação pendente (CTA "Continuar avaliação"
     quando `etapa_atual = avaliacao_assincrona`) + explicação LGPD quando há decisão.
   - **Consolidar Dashboard × Perfil do candidato** (`CAND-DASH-DUP-01`): hoje os dois listam
     candidaturas+status (duplicado). Definir papel de cada um — ex.: Dashboard = "minhas
     candidaturas + próximo passo acionável (CTA do funil)"; Perfil = "dados pessoais + edição".
     Sem isso, cabear o funil só aumenta a confusão entre as duas telas.
2. **[ALTA] Aposentar o `PerfilCandidatoRHPage` mock** — substituir pela visão real do
   candidato (consolidada com os workspaces) ou remover e redirecionar para a triagem real.
3. **[MÉDIA] Remover o legado `/testes/*`** (DISC/Raven/BigFive antigos + instruções +
   conclusão) e as duplicatas (MeuPerfilPage, Questionario*, InscricaoPage) — ~2.5k+ linhas mortas.
4. **[MÉDIA] Entrada admin** — menu/seção admin (gateado por role) para `/admin/*`, hoje
   só acessível por URL.
5. **[BAIXA] Plano para o `DevNavigationMenu`** — garantir que nada de produção depende dele
   (já é DEV-only, mas a navegação real precisa cobrir 100% antes de qualquer remoção).
