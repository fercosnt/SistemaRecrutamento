## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dashboard do Resend → operador humano → Vault | A credencial atravessa um canal humano (chat/clipboard/SQL Editor); é a janela de exposição mais provável desta fase |
| `vault.secrets` (cifrado em repouso) → `vault.decrypted_secrets` (view) | A descriptografia só deve acontecer sob `service_role`, dentro da RPC |
| Executor → SUMMARY / log de commit | Artefatos de planejamento são versionados e permanentes; uma chave escrita aqui é uma chave vazada para sempre |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-05-01 | Information Disclosure | Chave PROD transcrita em SUMMARY, log de MCP, mensagem de commit ou arquivo de planejamento | mitigate | Toda verificação usa `length(...)` ou `is not null`; opção preferida de fluxo é o operador executar `vault.create_secret` direto no SQL Editor; acceptance criteria grep-a o shape de chave em `.planning/`, `docs/`, `scripts/` e `supabase/` |
| T-36-05-02 | Tampering | Placeholder no Vault (`CHANGEME`, string vazia, chave de test-mode) produzindo 401 opaco no primeiro envio real a candidato | mitigate | Regra travada: sem chave real, NÃO se cria o segredo; o ramo (c) confirma por SQL que `ler_resend_api_key()` retorna NULL (graceful skip) |
| T-36-05-03 | Elevation of Privilege | Reutilização da chave do `cost-alerter` unifica o blast radius: revogar uma derruba os dois pipelines | mitigate | Checkpoint exige confirmação explícita de que a chave é nova e dedicada; débito da divergência já registrado no Plano 36-04 |
| T-36-05-04 | Repudiation | Registrar "provisionado" no HUMAN-UAT sem que o SQL tenha rodado | mitigate | O texto do HUMAN-UAT só pode afirmar o estado que os dois smokes retornaram; acceptance criteria amarra afirmação a resultado de SQL |
| T-36-05-05 | Denial of Service | Segundo `vault.create_secret` com o mesmo nome criando linha duplicada e leitura ambígua | mitigate | Higiene obrigatória antes de criar: consultar `vault.secrets` por nome e usar `vault.update_secret` se já existir |
