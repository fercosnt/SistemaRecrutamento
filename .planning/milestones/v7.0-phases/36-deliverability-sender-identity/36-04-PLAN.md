<objective>
Fechar o lado SQL do DELIV-02: o segredo mora no Vault, e existe exatamente um caminho legítimo e minimamente privilegiado para lê-lo em runtime.

Purpose: o schema `vault` NÃO é exposto ao PostgREST — sem uma wrapper `SECURITY DEFINER` em `public`, a EF da P38 não consegue ler `vault.decrypted_secrets` e o DELIV-02 vira "um cofre que ninguém abre". <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `service_role` (Edge Function) → schema `vault` | Ponto onde uma credencial em repouso vira credencial em runtime; é a fronteira que a RPC define |
| PostgREST (anon / authenticated JWT) → schema `public` | Toda função em `public` é potencialmente chamável via API REST se não tiver os privilégios revogados |
| Repo/ledger → PROD | A migration é aplicada por um caminho privilegiado (MCP) fora do fluxo normal de `db push` |
