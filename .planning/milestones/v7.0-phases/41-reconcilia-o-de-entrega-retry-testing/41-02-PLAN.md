Escrever a nova Edge Function `resend-webhook`: um endpoint público (`verify_jwt=false`) que o Resend chama nos eventos de entrega, verifica a assinatura **Svix** sobre o corpo bruto, mapeia `email.delivered`/`email.bounced`/`email.complained` para os status terminais e reconcilia a linha em `notificacoes_enviadas` por `provider_message_id` — completando a state machine `pendente→enviado→entregue/falhou/bounce/reclamado` (RECON-01, RECON-02).

Purpose: hoje `provider_message_id` é gravado no envio (P38) mas nunca reconciliado — o status final da entrega é invisível. Esta EF fecha a metade "entrega real" do loop. Cada peça tem gêmeo vivo: o esqueleto self-auth vem de `analise-candidato-individual` (trocando o Bearer pela verificação Svix), o mapa puro vem da forma do `EVENTO_MAP` de `notificar-candidato/helpers.ts`, o consumo de segredo do Vault espelha `ler_resend_api_key`.
Output: 3 arquivos novos da EF + 1 entrada em `config.toml`. **Zero contato com PROD** — só código + testes Deno. O deploy + registro do endpoint + provisionamento do secret são o plano GATED 41-05.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-41-04 | Spoofing | Webhook forjado marcando `entregue` falso | mitigate | `Webhook.verify` (Svix) obrigatória sobre o corpo BRUTO antes de qualquer escrita; assinatura inválida → 400, zero writes |
| T-41-05 | Tampering / Replay | Replay de webhook antigo | mitigate | Svix inclui `svix-timestamp` + tolerância (a lib rejeita fora da janela); `svix-id` disponível p/ dedupe |
