<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI/test run → destinatário | Um run em modo teste NUNCA pode alcançar um e-mail de candidato real |
| trigger/cron → EF (retry) | O backoff/cap governa quantas vezes a EF re-envia; sem cap seria loop de custo |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-41-01 | Information Disclosure / Spoofing | Envio a destinatário real num run de teste | mitigate | `exigirSinkTeste` hard-fail em modo=teste se o `to` efetivo não for `*@resend.dev`, chamado antes do fetch (DELIV-03) |
| T-41-02 | Denial of Service | Retry infinito / custo de e-mail | mitigate | `computeProximaTentativa` devolve `null` no cap 5 → linha fica `falhou`, sem novo retry; backoff exponencial espaça as tentativas |
| T-41-03 | Information Disclosure | PII/segredo em log ou mensagem de erro | mitigate | `exigirSinkTeste` não interpola o destinatário real na mensagem; `logSeguro` (allowlist) segue como único caminho de log |
</threat_model>
