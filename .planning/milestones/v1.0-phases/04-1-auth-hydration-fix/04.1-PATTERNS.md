### EDIT `src/store/authStore.ts` — add `hydrateFromSession(session)` action

**Analog:** `src/store/authStore.ts:296-340` (`initialize()` action — same file)

**Recommendation per RESEARCH §Open Questions Q2:** create new action `hydrateFromSession`, do NOT modify `setSession`. Reduces blast radius (legacy callers `setAdminSession` aliasing `setSession` mantêm comportamento sync-only).

**Imports pattern** (já existem no arquivo, linhas 20-25 — não tocar):

**Core hydration pattern** (copiar a estrutura completa de `initialize()` linhas 296-340; o `hydrateFromSession` deve aceitar `session: Session | null` em vez de chamar `getSession()`):
```typescript
// authStore.ts linhas 296-340 (initialize) — REPLICATE THIS SHAPE in hydrateFromSession
initialize: async () => {
  try {
    set({ isLoading: true })
    const {
      data: { session },
      error,
    } = await supabase.auth.getSession()

    if (error) {
      console.error('Erro ao buscar sessão:', error)
      get().clearAuth()
      return
    }

    if (session?.user) {
      const roleFromJwt = extractRole(session)
      const { profile, resolvedRole } = await fetchProfile(session.user.id, roleFromJwt)

      set({
        user: session.user,
        session,
        role: resolvedRole,
        profile,
        candidato:
          resolvedRole === 'candidato'
            ? (profile as CandidatoRow | null)
            : null,
        adminUser:
          resolvedRole === 'rh' || resolvedRole === 'administrador'
            ? (profile as UsuarioRHRow | null)
            : null,
        permissions: permissionsFromRole(resolvedRole),
        isAdmin: resolvedRole === 'administrador',
        isAuthenticated: true,
      })
    } else {
      get().clearAuth()
    }
  } catch (error) {
    console.error('Erro ao inicializar auth store:', error)
    get().clearAuth()
  } finally {
    set({ isLoading: false })
  }
},
```

**Key shape difference for `hydrateFromSession`:**
- Skip `supabase.auth.getSession()` — the listener already provides `session` directly.
- Skip `set({ isLoading: true })` — listener runs post-mount; `isLoading` is already `false`. Keeping it `true` would re-trigger RoleGuard spinner mid-flow. (RESEARCH §Common Pitfalls §Pitfall 6.)
- Skip `console.error('Erro ao inicializar auth store')` — listener cluster owns its own error path.

**Type/interface extension** (linha 84-88 em `AuthState`):
```typescript
// Add to AuthState interface:
hydrateFromSession: (session: Session | null) => Promise<void>
```

**Persist `partialize` is NOT touched** (linhas 439-444 — preservar `profile/candidato` exclusion per RESEARCH §Security §State leak across tabs).

### CREATE `src/features/auth/utils/waitForCandidatoHydrated.ts`

**Analog:** `src/features/auth/utils/extractRole.ts` (utility module convention) + `rememberMeStorage.ts` (utility folder location)

**Core utility pattern** (RESEARCH §Pattern 2 — exact target shape):
```typescript
/**
 * Aguarda candidato (legacy alias for `profile` when role==='candidato') ser
 * populado no store. Usado por submit handlers que precisam navegar para uma
 * rota que depende de `candidato.id` (LoginCandidatoPage, RedefinirSenhaPage,
 * CadastroMultiStepForm Step 4).
 *
 * Defense in depth: complementa Pattern 1 (listener centralized hydration).
 * O listener é assíncrono via setTimeout(0); submit handlers podem chamar
 * navigate() ANTES do fetchProfile resolver. Este helper bloqueia até o
 * store reportar `candidato !== null` OU hard timeout disparar.
 *
 * @param timeoutMs hard cap to avoid hanging forever (default 3000ms)
 * @returns true se candidato hidratou na janela; false em timeout (ou
 *   se role autenticou como rh/administrador, que não é candidato)
 */
export async function waitForCandidatoHydrated(
  { timeoutMs = 3000 }: { timeoutMs?: number } = {}
): Promise<boolean> {
  const start = Date.now()
  while (Date.now() - start < timeoutMs) {
    const { candidato, role } = useAuthStore.getState()
    if (candidato && role === 'candidato') return true
    if (role && role !== 'candidato') return false  // RH/admin path; nav happens elsewhere
    await new Promise((r) => setTimeout(r, 50))
  }
  return false
}
```

**Pitfall 7 compliance:** zero `console.*` calls (utility está sob auth surface — `pitfall7.grep.test.ts` `PHASE_3_AUTH_PATHS` cobre `src/features/auth` recursivo).

**Source:** Supabase official docs (Context7) + RESEARCH §Pitfall 2 + GH issue 762
**Apply to:** `src/App.tsx` listener (the only call site after Phase 1 consolidation)
**Citation:** `https://supabase.com/docs/reference/javascript/initializing` + `https://github.com/supabase/auth-js/issues/762`

```typescript
supabase.auth.onAuthStateChange((event, session) => {
  // Sync work first (no await) — avoid deadlock
  if (event === 'SIGNED_OUT') { clearAuth(); return }
  // Async work deferred via setTimeout(0)
  setTimeout(async () => {
    if (event === 'SIGNED_IN' || event === 'TOKEN_REFRESHED' || event === 'USER_UPDATED' || event === 'PASSWORD_RECOVERY') {
      await useAuthStore.getState().hydrateFromSession(session)
    }
  }, 0)
})
```
