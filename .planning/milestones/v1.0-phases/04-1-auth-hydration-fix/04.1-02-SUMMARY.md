## Decisions Made

- **Decision:** Created `hydrateFromSession` as a NEW action vs. rewriting `setSession`. **Rationale:** RESEARCH Q2 + PATTERNS.md §EDIT recommend new action. Reduces blast radius — `setAdminSession` legacy alias preserves existing sync semantics for RH login flow + ProtectedAdminRoute. Candidate flow gains the async DB fallback without rewriting all consumers.
- **Decision:** Skipped `set({ isLoading: true })` and `console.*` inside `hydrateFromSession`. **Rationale:** RESEARCH §Common Pitfalls (Pitfall 6 — re-trigger spinner mid-flow) + Pitfall 7 (T-4.1-04 zero-console invariant). Empty `catch` is intentional (matches extractRole convention from Phase 3); RoleGuard fallback handles bounce.
- **Decision:** PASSWORD_RECOVERY listed as a hydrate-triggering event alongside SIGNED_IN/TOKEN_REFRESHED/USER_UPDATED. **Rationale:** RESEARCH §Open Questions Q4 — Phase 3 password recovery flow lands on /candidato/perfil after `setNewPassword` resolves; without hydration the page renders with `candidato=null` (same INT-BLOCKER-1 manifestation).
- **Decision:** SIGNED_OUT branch placed BEFORE the setTimeout block (sync path). **Rationale:** PATTERNS.md §Pattern A explicit guidance — putting clearAuth inside setTimeout creates flash-of-unauth-state where the user briefly sees an authenticated UI while local state still reports authenticated. Sync clearAuth fires immediately on SIGNED_OUT; the next render sees the cleared state.
- **Decision:** RoleGuard 2b fallback uses `void useAuthStore.getState().initialize()` (NOT `await`). **Rationale:** React render functions cannot be async. The optimistic spinner gates the user; on the inevitable re-render after `set(...)` completes inside `initialize`, role will be populated and 2b's `if (currentRole === null)` check returns false. If still null, fallbackTriedRef.current is now true; bounces to /auth/login.
