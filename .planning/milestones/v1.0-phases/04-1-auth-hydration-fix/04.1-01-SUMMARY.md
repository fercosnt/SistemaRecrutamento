**2. [Rule 1 - Bug avoidance] file-scoped jest-dom triple-slash shim**
- **Found during:** Task 1 verification (tsc went 320 → 323)
- **Issue:** Initial `RoleGuard.test.tsx` produced 3 net-new TS errors `Property 'toBeInTheDocument' does not exist on type 'Assertion<HTMLElement>'`. The pre-existing `LoadingProgress.test.tsx` carries the same shape error (24 instances) — they were part of the 320 baseline as a pre-existing carryover from Phase 2.
- **Fix:** Added `/// <reference types="@testing-library/jest-dom" />` at the top of `RoleGuard.test.tsx`. The directive is resolved at the project level, so it incidentally unblocked LoadingProgress.test.tsx's 24 carryover errors as well — net tsc baseline movement: 320 → 296 (−24).
- **Files modified:** `src/components/__tests__/RoleGuard.test.tsx` (1 LoC at top of file)
- **Commit:** ed2e430
- **Why this is the right fix (not a Rule 4 architectural change):** the `tests/setup.ts` already imports `'@testing-library/jest-dom'` for runtime extension; the only missing piece was TS type augmentation. The triple-slash directive is the canonical, file-scoped way to opt into ambient module augmentation without polluting tsconfig.json's global `types[]` array (which is shared with non-test src/ compilation).
