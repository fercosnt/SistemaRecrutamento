# Phase 26 — UI Design Contract

> Visual and interaction contract for the **candidate-side funnel correction** (alcançabilidade & scoring). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a CORRECTION phase, not greenfield.** The candidate assessment surface already exists and its full contract was set in **`11-UI-SPEC.md`** (approved 2026-06-09). This document does **not** re-invent the palette, typography, spacing, or shell — it **inherits** them and specifies only the two narrow UI deltas this phase introduces:
>
> 1. **Assessment-card state contract** — derive each card's completion state from the candidate's OWN rows (via a neutral status RPC) instead of the phantom `entry.status` field (FUNIL-12), and add a **cognitivo card** gated by `vaga.aplica_cognitivo` that routes to the real prova-cognitiva route (FUNIL-08).
> 2. **Honest wait-state copy contract (UX-01)** — one canonical pt-BR string, `"Acompanhe o andamento pelo seu painel."`, replacing every "avisaremos por e-mail" promise across 6 screens.
>
> Everything else in Phase 26 (`pontuar_sjt` integrity, SJT cargo/itens_ids filtering, the unique-index drop, n8n server-side dispatch) is backend/data with **no UI surface** and is intentionally **out of scope** for this contract. The candidate **never** sees scores, thresholds, or pass/fail (RNF-07a).

The candidate side is the **glass-over-gradient** persona surface (translucent white over the brand gradient). Inherited from `11-UI-SPEC.md`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#00109E` brand-primary gradient (`BackgroundImage background="gradient"`) | Full-page background behind all glass |

| Destructive | `#EF4444` (`--destructive` / `--semantic-error`) | Load-error iconography ONLY — there are **no destructive candidate actions** in this phase |

**Accent (`#35BFAD`) reserved for — explicit list (this phase):**
1. The **Concluído** status: the `CheckCircle2` icon + "Concluído" pill text on any completed assessment card (including the new cognitivo card).
2. The **all-done** panel's large `CheckCircle2` ("Tudo concluído!").

Accent is **NOT** used for: card CTAs, the "Em andamento" / "Pendente" states, the cognitivo card CTA, links, or generic hover. Those stay glass-white (`bg-white/15` → `hover:bg-white/25`, white text). This keeps accent rare = "your work is recorded/complete".

**Status colors are neutral, RNF-07a-safe** — never red/green pass-fail. The candidate never sees a "failed" tint; scoring outcomes are invisible to them. Full mapping in the Card State Contract below.

## Card State Contract (FUNIL-12 + FUNIL-08)

**The load-bearing change:** each card's completion state is derived from the candidate's **own rows** (`scores_candidato` / `respostas_avaliacao`) via a **neutral status RPC** (booleans per test — no raw score, no threshold, no gabarito ever crosses to the candidate; RNF-07a + answer-key protection). It is **NOT** read from `entry.status`, which does not exist on `testeAplicavelSchema` (that jsonb is vaga-level config — the phantom field the current `AvaliacaoContainer.tsx:312` reads).

The container already owns the neutral presentation helper `statusInfo()` (`AvaliacaoContainer.tsx:117-127`) and the CTA-label branch (`:249-251`). This contract locks what each derived state renders. Keep the existing neutral visual language — do not introduce pass/fail color.

| State | When (from own rows) | Status pill | Icon | Pill tint | CTA |
|-------|----------------------|-------------|------|-----------|-----|
| **pendente** | no own rows for this test | **Pendente** | `Circle` | `text-white/70`, `bg-white/10` | **Começar avaliação** (accent-free glass-white GlassButton, `min-h-[44px]`) |
| **em_andamento** | autosave / partial rows exist, not yet submitted | **Em andamento** | `CircleDot` | `text-white/70`, `bg-white/10` (neutral — same tint as pendente, distinct icon + label + CTA only) | **Continuar avaliação** |
| **concluído** | a submitted/scored own row exists for this test | **Concluído** | `CheckCircle2` | `text-[#35BFAD]` (the single accent touchpoint per card) | none — pill only, no button |
| **bloqueado / indisponível** | wrong-etapa / not-yet-reachable | **Indisponível** | `Lock` | `text-white/60`, `bg-white/10` | none — pill only |

**Rules:**
- `em_andamento` MUST be visually distinct from `pendente` **only** via icon (`CircleDot` vs `Circle`), label ("Em andamento" vs "Pendente"), and CTA ("Continuar" vs "Começar") — **never** via a warning/color tint. Both are the same neutral white tint. This makes progress legible without implying evaluation.
- `concluído` is the **only** card state that uses accent (`#35BFAD`). Never tint a pending/in-progress card with accent.
- No card ever shows a red "reprovado"/"falhou" state to the candidate. A failed score is invisible — a completed-but-below-threshold test still reads **Concluído**.
- The `allDone` derivation (`AvaliacaoShell` `:147-148`) counts a card done when its derived state is `concluído`; unchanged logic, new source of truth.

### Cognitivo card (FUNIL-08 — new, conditional)

A cognitivo card is rendered inside the same `deriveCards`/`AvaliacaoShell` flow, subject to these rules:

| Aspect | Contract |
|--------|----------|
| **Gate** | Rendered **only** when `vaga.aplica_cognitivo === true`. NOT gated by the template entry (`cargoTemplates.ts:71` always emits cognitivo) — the vaga column is the single source of truth. |
| **Label** | **Avaliação cognitiva** (already in `CONTAINER_TESTE_CONFIG.cognitivo`; do not rename). |
| **Route** | `/candidato/prova-cognitiva/:candidaturaId` (the **real** route — replaces the stub `/candidato/avaliacao/:id/cognitivo` at `AvaliacaoContainer.tsx:88-93`). |
| **Visual** | Identical `GlassCard variant="white"` treatment as every other card — 20px/600 title, 14px meta "Tempo estimado: ~{N} min", right-aligned status pill, `min-h-[44px]` CTA. No special styling; it is a peer card. |
| **State** | Same four-state contract above, derived from the candidate's own cognitivo rows via the neutral status RPC (not the phantom field). |
| **CTA** | **Começar avaliação** (pendente) / **Continuar avaliação** (em_andamento) — accent-free glass-white, same as siblings. |
| **Ordering** | Cognitivo appears **last** in the card list (after SJT/redação/comportamental) — it is the deepest async assessment. |

**Route ↔ gate invariant (contract test, per CONTEXT):** the etapa in which the cognitivo card appears (`avaliacao_assincrona`) MUST equal an etapa the `pontuar_cognitivo` RPC gate accepts. The UI card and the server gate are two ends of one contract — do not let the card route to a screen the RPC will reject.

## Copywriting Contract

All copy pt-BR. Product-language rule (LGPD-04): use **"avaliação comportamental/cognitiva"**, NEVER "teste psicológico". Candidate copy is neutral and reassuring — it never references scores, thresholds, percentages, or aprovado/reprovado.

| Element | Copy |
|---------|------|
| Primary CTA (card, not started) | **Começar avaliação** |
| Primary CTA (card, in progress) | **Continuar avaliação** |

### Honest Wait-State Copy (UX-01) — canonical string + 6-screen replacement map

**Canonical string (locked by CONTEXT.md):**

> **`Acompanhe o andamento pelo seu painel.`**

Rationale: the panel/dashboard is the source of truth for status — the system has **no** e-mail notification infra, so every "avisaremos por e-mail" promise is dishonest. Mirror the already-correct patterns at `VagaDetalhePage.tsx:319` ("Acompanhe o status da sua candidatura no dashboard") and `DashboardCandidatoPage.tsx:186` ("Acompanhe seu progresso no processo seletivo").

Replace each string below with a grammatically-fitted use of the canonical line. **Remove every e-mail promise entirely** — do not soften, do not keep "por e-mail".

| # | File : line | Current (dishonest) | Replacement |
|---|-------------|---------------------|-------------|
| 1 | `AvaliacaoContainer.tsx:209` (all-done body) | "Você concluiu todas as avaliações desta etapa. Avisaremos sobre os próximos passos por e-mail." | **"Você concluiu todas as avaliações desta etapa. Acompanhe o andamento pelo seu painel."** |
| 2 | `RedacaoEditorScreen.tsx:278` (redações-concluídas body) | "Avisaremos sobre os próximos passos por e-mail." | **"Acompanhe o andamento pelo seu painel."** |
| 3 | `DevolutivaBigFiveView.tsx:157` (devolutiva-preparando body) | "Volte em alguns instantes — avisaremos por e-mail quando estiver pronta." | **"Volte em alguns instantes. Acompanhe o andamento pelo seu painel."** |
| 4 | `ProvaCognitivaScreen.tsx:82` (`postSubmit`) | "Prova registrada. Avisaremos sobre os próximos passos." | **"Prova registrada. Acompanhe o andamento pelo seu painel."** |
| 4b | `ProvaCognitivaScreen.tsx:18` (prose doc-comment) | "...sees the NEUTRAL 'Prova registrada. Avisaremos sobre os próximos passos.'..." | Update the comment to quote the new `postSubmit` string verbatim (keeps the grep guard + docs honest). |
| 5 | `SolicitarRevisaoCTA.tsx:45` (`dialogBody`) | "Sua solicitação será enviada à equipe responsável, que revisará a decisão. Avisaremos você sobre o resultado." | **"Sua solicitação será enviada à equipe responsável, que revisará a decisão. Acompanhe o andamento pelo seu painel."** |
| 6 | `SuporteRHPage.tsx:162-163` (RH-facing) | "Recebemos sua solicitação e nossa equipe técnica irá analisá-la em breve. Você receberá atualizações por e-mail." | **"Recebemos sua solicitação e nossa equipe técnica irá analisá-la em breve. Acompanhe o andamento pelo seu painel."** |

**Notes:**
- Screen 6 (`SuporteRHPage`) is **RH-facing**, not candidate-facing, but CONTEXT.md explicitly includes it under the same honesty rule (RH also tracks status in its own hub/painel — the e-mail promise is equally false there). Apply the canonical string; do not add an RH-specific variant.
- **Do NOT touch** the consent copy at `AutorizacoesStep.tsx:58/93/185` — that is legitimate LGPD consent language, not a wait-state promise.
- All 6 replacements keep the **existing** visual treatment (glass panel, `CheckCircle2`/`AlertCircle` icon, `text-white/70`–`/80` body, `p-12` centered state). Only the string changes; no layout, color, or typography change.

**CI grep guard (regression net, per CONTEXT):** add/extend a guard test that BANS re-introduction of the e-mail-promise pattern in the candidate wait-state screens — e.g. `/avisaremos[\s\S]*por e-?mail/i` and `/receber[áa][\s\S]*por e-?mail/i` across the 6 files above. The guard should still permit legitimate transactional-e-mail copy elsewhere (password reset `RedefinirSenhaPage`, consent, `Notificar candidato por email` RH toggle) — scope the guard to the wait-state files, not a global src ban.
