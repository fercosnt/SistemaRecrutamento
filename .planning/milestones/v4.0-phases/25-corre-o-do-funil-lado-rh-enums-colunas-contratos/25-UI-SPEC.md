# Phase 25 — UI Design Contract

> Visual and interaction contract for **Correção do Funil (lado RH — enums, colunas & contratos)**.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Framing (binding):** This is a HARDENING / CORRECTION phase, NOT a greenfield UI build.
> It rewires existing RH (recruiter, desktop-first) surfaces to the enums/columns that exist,
> and removes dead affordances. **No net-new visual language is introduced.** Every contract
> below reuses the established design system: Tailwind + shadcn/ui (Radix) + the Beauty Smile
> glass UI (`src/components/ui/glass.tsx`). Where a field is not touched by this phase, it is
> marked **inherited (no change)** — the checker should treat those as pre-satisfied by the
> existing system, not as new specs to enforce.

## Spacing Scale

Declared values (multiples of 4). This phase inherits the existing scale from `globals.css` `--spacing-*`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (card internals `gap-2`) |
| — | 12px | Kanban card padding (`p-3`) + column gap (`gap-3`) — established grid rhythm |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Empty-state / not-found vertical breathing (`py-12`) |
| 3xl | 64px | Page-level spacing |

Exceptions: **touch target minimum 44px** (`min-h-11` / `min-h-[44px]`) for every interactive control — matches existing `AsyncState` retry button and `NotFoundPage` back-link. `12px` is retained (multiple of 4) because the live Kanban rhythm depends on it — do not "round" it to 16px, that would be a gratuitous visual regression.

## Typography

RH desktop surfaces. Exactly 4 sizes, 2 weights (mirrors `NotFoundPage` / prior RH UI-SPECs).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / dense body | 14px (`text-sm`) | 400 | 1.5 |
| Body | 16px (`text-base`) | 400 | 1.5 |
| Section / card heading | 20px (`text-xl`) | 600 | 1.2 |
| Page display / not-found numeral | 28px (`text-3xl`) | 600 | 1.2 |

Weights: **regular 400** + **semibold 600** only. Bold (700) is NOT used — size + weight-600 carry emphasis (established `NotFoundPage` rule). Kanban card names use `text-sm`/600; column titles `text-sm`/600 with count.

## Color

Inherited from `globals.css` (60/30/10 already established across the RH shell). This phase adds **no new color**; it only reassigns which stages/labels render.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` / `neutral-50 #F8F9F9` (`--background`) | RH page background, surfaces |
| Secondary (30%) | glass surfaces (`Glass variant="white"` = `bg-white/15`) + brand primary `#00109E` (`--primary`) RH chrome/sidebar/nav | Cards, sidebar, nav, Kanban columns |
| Accent (10%) | turquoise `#35BFAD` (`--accent` / brand-accent) | see reserved-for list |
| Destructive | `#EF4444` (`--destructive`) | Reject / destructive confirmation only |

Accent (`#35BFAD`) reserved for: **primary CTA buttons** (e.g. Editar Vaga "Salvar alterações"), the **not-found back-link**, **active nav/tab indication**, and the **Kanban card avatar fill**. It is NOT applied to every interactive element, badges, or column headers. Kanban per-column gradient headers keep their existing distinct hues (blue/cyan/purple/teal/orange/indigo) — those are categorical stage identifiers, not the brand accent.

Score color scale (inherited, reuse `getScoreColor`): ≥80 green-400 · ≥60 blue-400 · ≥40 yellow-400 · <40 red-400 · null white/50. Do not re-invent.

## Phase Surface Contracts

The load-bearing part of this phase. Five narrow surfaces; each reuses an existing pattern.

### 1. Kanban rewire — real 6-stage pipeline (`src/components/KanbanBoard.tsx`, FUNIL-03/06)

**Column set (binding).** Replace the 4 dead M1 columns (`bigfive`/`disc`/`raven`/`cultura`) with the **6 real working stages**, in funnel order, using the canonical labels already single-sourced in `triagemService.ETAPA_M2_LABELS`:

| Order | `etapa_processo` value | Column label (pt-BR) | Suggested glyph | Suggested header hue |
|-------|------------------------|----------------------|-----------------|----------------------|
| 1 | `inscricao` | Inscrição | 📥 | from-blue-500 to-blue-600 |
| 2 | `triagem` | Triagem | 🔍 | from-cyan-500 to-cyan-600 |
| 3 | `avaliacao_assincrona` | Avaliação Assíncrona | 📝 | from-purple-500 to-purple-600 |
| 4 | `entrevista_online` | Entrevista Online | 🎥 | from-teal-500 to-teal-600 |
| 5 | `entrevista_presencial` | Entrevista Presencial | 🤝 | from-orange-500 to-orange-600 |
| 6 | `decisao_final` | Decisão Final | ⚖️ | from-indigo-500 to-indigo-600 |

- Labels are the **binding contract** (must equal `ETAPA_M2_LABELS`, the single source of truth — do not hardcode a second copy). Glyph + hue are **Claude's discretion**, but each column must be visually distinct and the glyph must be `aria-hidden`.
- Column visual language = **reuse existing** (`Glass` column with gradient header + glyph + label + live count; drop-target "Solte aqui" indicator; draggable `Glass variant="white"` cards). No new column component.
- Responsive grid: **6 drop columns** (adjust the current `lg:grid-cols-[repeat(7,…)]` → `repeat(6,…)`; keep 2-col mobile / 4-col tablet fallback).
- **Terminals (`aprovado` / `rejeitado`) are NOT drop columns.** A terminal is not a work queue. Contract: a candidatura in a terminal state renders a **terminal badge/pill on its card** (green `Aprovado` / red `Rejeitado`, using the existing status color language) and remains reachable via the panel's existing etapa filter (`ETAPA_M2_OPTIONS` already lists both terminals). This also closes the reject-without-trail vector at the UI: you cannot drag a card into "Rejeitado" (there is no such column) — rejection goes only through the sanctioned justification path.
- Delete the `console.warn`-into-`triagem` fallback grouping; every live etapa now maps to a real column, so unmapped-etapa noise disappears.

### 2. Gated mock screens — empty-state (A14 `/rh/configuracoes`, A37 RH `MeuPerfilPage`, UX-06)

**Scope of replacement (binding):** the empty-state **replaces the entire mock content region** of each page (the fake user list / the stub save-dados/senha/foto forms). **Keep** the RH persona shell (nav/sidebar) and the page header/title so the recruiter still knows where they are. **Do NOT** DEV-gate and **do NOT** delete the route (offboarding-LGPD minimum fix; real feature → M5).

**Pattern:** a single centered `GlassCard` (reuse the glass empty block used across the app — same typographic rhythm as `AsyncState`'s `EstadoVazio`: muted lucide icon, heading 20px/600, body 14–16px/400 in `text-muted-foreground`/`white/70`, `py-12`, no CTA because the feature is unavailable). No retry, no primary action.

| Surface | Icon (lucide) | Heading | Body |
|---------|---------------|---------|------|
| `/rh/configuracoes` (A14) | `Users` / `Settings` | Gestão de usuários ainda não disponível | Esta área está em desenvolvimento e chegará em uma próxima atualização. Nenhuma ação de usuário está disponível aqui por enquanto. |
| RH `MeuPerfilPage` (A37) | `UserRound` | Edição de perfil em breve | A edição dos seus dados, senha e foto estará disponível em uma próxima atualização. |

### 3. Hub not-found state (`src/features/hub-candidato/components/HubCandidatoRH.tsx`, UX-03)

Today the hub degrades silently to a generic `"Candidato" / "—"` header when the `:id` (candidaturaId) doesn't resolve. Contract: render an explicit **in-shell not-found state** (a valid route with an unresolvable id — NOT the global `NotFoundPage`, which is the catch-all for unknown routes).

- **Pattern:** centered `GlassCard` within the RH hub layout (persona shell preserved), mirroring `NotFoundPage`'s glass composition but scoped to the hub content area.
- **Copy:** heading (20px/600) "Candidatura não encontrada"; body (16px/400) "Não encontramos essa candidatura. Ela pode ter sido removida ou o link está incorreto."
- **Back affordance (single accent):** `GlassButton variant="accent"` with a leading `ArrowLeft` (aria-hidden), visible text label **"Voltar aos candidatos"** → `/rh/candidatos`, `min-h-11`. No icon-only.
- Trigger: nav now passes `candidatura.id` (fix `CandidatosRHPage.handleVerPerfil` + `KanbanBoard.onViewPerfil` forward); the not-found renders when the query resolves to no row for that id.

### 4. Dead-affordance removal (UX-06) — decision already locked in CONTEXT = **remove/hide, not disable**

| Affordance | Location | Action | What fills the gap |
|------------|----------|--------|--------------------|
| Hardcoded badges "12" / "5" | `RHSidebar` L74/L80 | **Remove** the badge element (never render "0") | Row reflows tighter; label stands alone — no gap |
| Global search box (no-op) | `RHTopBar` L84–95 | **Remove** the search input + `handleSearch` | TopBar reflows around remaining real controls |
| "📚 Usar da Biblioteca" / "Preview" template (no-op) | `CriarEditarVagaPage` | **Remove** the buttons | Adjacent real form controls remain; no dangling gap |
| Tiles "—" (placeholder values) | dashboard tiles | **Wire to real count if a query exists; otherwise remove the tile** so the grid reflows | Real data or fewer tiles — never an em-dash placeholder |
| `avançar` / `rejeitar` no-op buttons | `DecisaoFinalPage` embedded `ComparativoScreen` (`onAvancar={()=>{}}`/`onRejeitar={()=>{}}`) | **Hide** the two dead buttons (do not render) | Comparison content stays visible; the real decision path is `registrar_decisao` elsewhere on the page |

**No visual regression rule:** after removal, no empty container, dangling border, orphaned label, or `0`/`—` placeholder may remain. Layouts must reflow, not leave holes.

### 5. Editar Vaga (`CriarEditarVagaPage`, FUNIL-04/05) — wiring, minimal new visual surface

- Uses **existing form controls** only (inputs/selects/radio/`configVagaService` blocks). No new visual language.
- Hydration now reads **real columns** (`faixa_salarial_min/max`, `jornada_trabalho`, `responsabilidades`/`sobre_cargo`, `requisitos_*`, `diferenciais`/`perfil_ideal`) — visible effect: fields that were blank/broken now populate on edit+reload. The visual contract is **fidelity** (edit → reload keeps values), not a new layout.
- Primary CTA on the edit path = **"Salvar alterações"** (accent). Config (pesos/testes) already persists; do not change its controls.

## Interaction Contracts

| Interaction | Contract |
|-------------|----------|
| Reject a candidate (destructive) | Justification is **required** — the reject action stays **disabled until a justification is entered**; server enforces the audit trail (trigger + GUC). Confirmation copy states the rejection is recorded for audit (RNF-07a). No path rejects a candidate without a trail (incl. Kanban — there is no "Rejeitado" drop column). |
| Move card between stages (Kanban DnD) | Drag → drop on one of the 6 working columns updates `etapa_atual` via the M2 flow (`updateCandidaturaEtapa` / `avancar_etapa` trigger). Terminals are not drop targets. |
| Not-found (hub) | Single accent back affordance "Voltar aos candidatos"; ≥44px; visible label. |
| Empty gated screens | No action available; empty-state carries no CTA. |
| Edit vaga | "Salvar alterações" persists base fields + status radio + existing config; reload preserves all. |
