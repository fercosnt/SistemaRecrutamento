# Phase 9 — UI Design Contract

> Visual and interaction contract for the 3 read-only internal admin pages of Phase 9. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note (read first)

Phase 9 is **primarily backend/infra**. The ONLY frontend surface is **3 read-only internal ADMIN pages** gated by role `administrador` (RLS uses `'administrador'`, not `'admin'` — confirmed Phase 7/8):

| Route | Purpose | RF |
|-------|---------|----|
| `/admin/ai-logs` | Read-only filterable table of `ai_call_logs` (filter: candidato_id, vaga_id, call_type, status) + row → detail modal | RF-PL-26 |
| `/admin/prompt-versions` | Version list grouped by `call_type` + side-by-side diff + "Promote to canary" / "Promote to active" / "Rollback" buttons (each calls a SECURITY DEFINER RPC) | RF-PL-27 |
| `/admin/ai-costs` | Recharts aggregation of `ai_cost_daily` (by vaga, call_type, day) + paginated table | RF-PL-28 (Should) |

These are **desktop-first internal RH/Admin operational/compliance tooling** — NOT candidate-facing, NOT mobile-first, low-traffic. The contract below **reuses the existing Beauty Smile admin theme + glass UI + the established RH layout** (`RHLayout` = `BackgroundImage darkBlue` + `RHSidebar` + `RHTopBar`). **No net-new design system. No new tokens.** These pages work over the schema even before any real AI consumer exists (consumers arrive Phase 10+), so empty states are the default state at ship time.

**Source:** 09-CONTEXT.md (Area 1, Claude's Discretion: "Layout/composição das 3 páginas admin (read-only) seguindo design system Beauty Smile + glass UI"); PRD §3.1 Admin UI + §4 personas + §6.5 RF-PL-26/27/28/29.

## Spacing Scale

Declared values (must be multiples of 4 — matches existing Tailwind spacing):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, badge inner padding |
| sm | 8px | Compact spacing between filter controls, table cell vertical padding |
| md | 16px | Default gap between cards/sections, `p-4` main content (mobile) |
| lg | 24px | `p-6` (`lg:p-6`) main content padding (desktop), GlassCard inner padding |
| xl | 32px | Gap between major page regions (filter bar → table → pagination) |
| 2xl | 48px | Empty-state vertical breathing room (centered block) |
| 3xl | 64px | Reserved; not expected on these dense data pages |

Exceptions: Table rows are dense — use `py-2` (8px) cell padding, not the candidate-facing comfortable spacing. Click target on table rows must remain ≥40px row height for usability.

## Typography

Exactly 3 sizes + 1 mono role, 2 weights. Reuse existing `--font-weight-*` tokens (use only 400 + 600 for this phase).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Page heading (h1) | 28px | 600 (semibold) | 1.2 |
| Section / card title | 20px | 600 (semibold) | 1.2 |
| Body / table cell / label | 16px | 400 (regular) | 1.5 |
| Mono (hash, semver, JSON, IDs) | 14px | 400 (regular) | 1.5 — `--font-family-mono` |

Notes:
- Use **600** for emphasis (active version, alert thresholds) — never bold 700/800 on these pages.
- Truncate `content_hash` to 8 chars in mono (RF-PL-27); full hash in tooltip.
- Table column headers: 16px / 600.

## Color

These pages render on the **dark blue admin background** (`BackgroundImage darkBlue`, base `#00109E`) with glass surfaces on top — NOT the white candidate surface. The 60/30/10 split below is expressed for that admin context.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#00109E` (brand-primary / `--primary`, the darkBlue background) | Page backdrop behind all glass surfaces |
| Secondary (30%) | glass surfaces over the backdrop (`GlassCard` / `GlassPanel`, translucent white) | Cards, filter bar, table container, modal, chart panels |
| Accent (10%) | `#35BFAD` (brand-accent / `--accent`) | Primary action emphasis ONLY (see reserved list) |
| Destructive | `#EF4444` (`--destructive`) | Rollback action + error/failed states ONLY |

**Accent (`#35BFAD`) reserved for:** the single primary action per page — i.e. the **"Promote to active"** GlassButton on `/admin/prompt-versions`, active-filter chip highlight, and the active-version indicator badge. NEVER on every interactive element, NEVER on table rows, NEVER on secondary buttons.

**Semantic status colors (status badges only — already in chart/semantic tokens):**
- `success` `#10B981` (`--chart-4`) → `success=true` log row, healthy cost (within R$ 0,38 baseline).
- `warning` `#F59E0B` (`--chart-5`) → error_rate 5–10% / cost approaching R$ 1,00 p95 guardrail.
- `destructive` `#EF4444` → `success=false` log row, error_rate >10%, cost > R$ 1,00.

**Chart palette (`/admin/ai-costs`, recharts):** use `--chart-1..5` in order (primary `#00109E`, accent `#35BFAD`, secondary `#BB965B`, success `#10B981`, warning `#F59E0B`) via the vendored `chart.tsx` config. Do not introduce ad-hoc hex chart colors.

## Copywriting Contract

All copy in **pt-BR** (project convention: domain in pt-BR). **Forbidden-string note (LGPD-04 / RNF-12):** product copy on these pages must NEVER contain "teste psicológico", "teste psicotécnico", "psicotécnico", "laudo psicológico", or "psicólogo" — the Vitest grep guard scans `src/`. Use "avaliação comportamental/cognitiva".

| Element | Copy |
|---------|------|
| Primary CTA — prompt-versions | `Promover para ativa` (accent GlassButton; precedes alert-dialog confirm) |
| Secondary CTA — prompt-versions | `Promover para canário (10%)` (neutral GlassButton) |
| Destructive CTA — prompt-versions | `Reverter` (destructive GlassButton; opens confirm dialog) |
| Diff trigger | `Comparar versões` (enabled when exactly 2 versions selected; tooltip when 0/1: `Selecione duas versões para comparar`) |
| Filter labels — ai-logs | `Candidato`, `Vaga`, `Tipo de chamada`, `Status` (Select dropdowns) |
| Clear filters | `Limpar filtros` |
| Empty state heading — ai-logs | `Nenhuma chamada de IA registrada ainda` |
| Empty state body — ai-logs | `As Edge Functions de IA do funil começam a registrar chamadas a partir da Fase 10. Quando houver dados, eles aparecerão aqui com filtro por candidato, vaga e tipo de chamada.` |
| Empty state heading — prompt-versions | `Nenhuma versão de prompt sincronizada` |
| Empty state body — prompt-versions | `As versões são hidratadas pelo CI (sync-prompts) ao mergear templates em main. Rode o sync ou faça merge de um template para ver as versões aqui.` |
| Empty state heading — ai-costs | `Sem dados de custo no período` |
| Empty state body — ai-costs | `A agregação diária de custo roda via pg_cron às 01:30 UTC. Selecione outro mês ou aguarde a primeira execução.` |
| Loading state | shadcn `Skeleton` rows (table) / skeleton blocks (charts) — não usar spinner em página cheia |
| Error state — query failure | `Não foi possível carregar os dados. Verifique sua conexão e tente novamente.` + botão `Tentar novamente` (refetch) |
| Error state — RPC failure (promote/rollback) | Sonner toast: `Falha ao {ação}: {mensagem do servidor}.` (surface the RPC RAISE EXCEPTION message verbatim — e.g. "canary_pct must be between 1 and 50") |
| Success — RPC ok | Sonner toast: `Versão {semver} de {call_type} {ação} com sucesso.` then invalidate query |
| Access denied (non-administrador) | route-guarded; if reached: `Acesso restrito a administradores.` |

### Destructive Actions

| Action | Confirmation approach |
|--------|----------------------|
| `Reverter` (rollback_to_version) | `AlertDialog`. Title: `Reverter prompt ativo?`. Body: `A versão ativa de {call_type} será desativada e a versão {semver} reativada. Esta ação é registrada na trilha de auditoria (data_deletion_log). Confirmar?`. Confirm button `Reverter` (destructive); cancel `Cancelar`. |
| `Promover para ativa` (promote_canary_to_active) | `AlertDialog` (non-destructive but state-changing in prod). Body: `Isto torna {semver} a versão ativa de {call_type} e deprecia a versão atual. Propagação em <60s, sem redeploy. Confirmar?`. Confirm `Promover`; cancel `Cancelar`. |
| `Promover para canário` (promote_to_canary) | Inline confirm via `AlertDialog` (lighter): `Roteará 10% do tráfego de {call_type} para {semver}. Confirmar?`. |

All three RPCs are SECURITY DEFINER granted to `administrador` only; the UI must assume the RPC re-validates and must render the server's RAISE EXCEPTION message on failure rather than a generic string.

## Page-Level Interaction Notes (for executor + planner)

**`/admin/ai-logs` (RF-PL-26):**
- `GlassCard` filter bar (4 Selects + `Limpar filtros`) above a `GlassCard`-wrapped `table.tsx`.
- Columns: `created_at`, `candidato_id`, `vaga_id`, `call_type`, `provider`, `model_id`, `prompt_version (semver)`, `success` (status badge), `parsed_score`, `cost_usd`, `latency_ms`.
- Row click → `Dialog` showing `parsed_reasoning` (formatted) + `raw_response` (mono JSON in `scroll-area`).
- Server pagination 50 rows via `pagination.tsx`. **PII reminder (security gate precedent):** never `select('*')` — the table reads an explicit allowlist of columns; PII columns (e.g. `curriculo_nome_original`) must not enter the client projection.

**`/admin/prompt-versions` (RF-PL-27):**
- Versions grouped by `call_type` (use `Accordion` or `tabs.tsx` per call_type). Each row: `semver`, `content_hash` (8-char mono + tooltip full), status badges (`is_active` accent, `is_canary` warning, `canary_pct`), `deployed_at`, `deprecated_at`.
- Selecting exactly 2 rows enables `Comparar versões` → side-by-side diff of `system_template` + `user_template` (mono, line-level; a simple two-column diff is sufficient — no heavy diff lib required).
- Action buttons per row gated by row state (e.g. `Promover para ativa` only on a canary row; `Reverter` only on a deprecated <1y row). Disabled buttons get a tooltip explaining why.

**`/admin/ai-costs` (RF-PL-28, Should):**
- Month filter (`Select`). Three recharts in `GlassCard`s via `chart.tsx`: line (daily cost 30d), bar (top 10 vagas), pie (by call_type). Below: paginated `ai_cost_daily` table.
- Annotate the R$ 0,50/candidato (RNF-10) and R$ 1,00 p95 guardrail (PRD §2.4) as reference lines / threshold markers where the chart supports it.
