# Phase 15 — UI Design Contract

> Visual and interaction contract for **Decisão Final Auditável & LGPD Art. 20**. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Three surfaces, three personas — all on the ESTABLISHED Beauty Smile design system (locked since M1; matches Phase 8/10/11/14 UI-SPECs).** This phase introduces NO new tokens, NO new shell, NO new primitives — only NEW compositions of the existing glass + RH-panel layers.
>
> 1. **RH consolidated decision dashboard** (desktop-first, internal admin persona, role-gated) at `/rh/candidato/:id/decisao` on the existing `RHLayout` + `Glass` brand surface. Renders the `consolidar-decisao-final` EF output: a **consolidated score** (weighted aggregate of per-etapa `scores_candidato` via `vaga.pesos_avaliacao` — AGGREGATE, never re-score), a **per-etapa breakdown** (each etapa's score + weight + N/A for missing/unapplied etapas), and a **deterministic textual recommendation** (templated from the breakdown, no LLM call — advisory only, RNF-07a). It embeds the **Phase-10 Comparativo verbatim** (`ComparativoScreen`/`useComparativo`/`exportComparativo`/`comparativo-candidatos` EF) scoped to the finalists in `decisao_final`, for side-by-side comparison. Below the dashboard, the **final-decision capture form**: a 3-option `decisao` selector (`aprovado`/`rejeitado`/`em_espera`) + a mandatory justificativa `textarea` (≥50 chars, validated client + DB CHECK) → writes `decisao_final` with `por_usuario NOT NULL` (LGPD-02 structural guardrail) and fires the terminal `avancar_etapa()` transition. One decision per candidatura; an amendment is a NEW auditable row (append-only), never a silent edit.
> 2. **Candidate LGPD Art. 20 explanation page** (mobile-first, public glass-over-gradient persona) at `/candidato/explicacao/:id`. Role-gated (`RoleGuard role="candidato"` + RLS own-candidatura) and only reachable after a `decisao_final` with `decisao='rejeitado'` exists. Shows a **respectful, NON-CLINICAL reason** (derived from the RH justificativa) + a **high-level result** — and **NEVER** raw trait scores, bands, percentiles, or psychometrics (RNF-07a / LGPD-04). A **"Solicitar revisão por pessoa natural"** CTA sets `decisao_final.revisao_solicitada_em` (existing column — no new table) and notifies the responsible RH (`vaga.created_by`) via the existing N8N webhook. Visiting the page stamps `explicacao_solicitada_em`.
> 3. **Admin bias-audit view** (desktop-first, admin-only — keep minimal) at `/admin/bias-audit`, modeled on the existing `AiCostsPage` admin pattern. Shows the latest `bias_audit_log` snapshot (selection-rate by **AGE band** with the 4/5 EEOC adverse-impact ratio), an **honest limitation banner** (race/gender NOT collected by design — LGPD-01 minimization), a **manual "Gerar snapshot"** trigger, and a **CSV export** (reuse the `AiCostsPage` download idiom). No charts library required for V1; a simple `table` suffices.
>
> **Binding spec:** `.planning/REQUIREMENTS.md` (DECISAO-01..04, LGPD-02, LGPD-03) + `15-CONTEXT.md` (4 grey areas LOCKED). Reuse-first: this phase composes existing components and adds the minimum new surfaces. **Out of scope:** WCAG AA cross-screen hardening → Phase 16 (LGPD-05) — note it, do NOT fully spec it; race/gender bias dimensions (protected attributes not collected); cron-scheduled snapshots (V1 is admin-triggered); AI-generated rejection letter (backlog §3.2).

## Typography

Family: Helvetica Neue (`--font-family`). Exactly 4 sizes, 2 weights. Body line-height 1.5, heading line-height 1.2. Candidate surface text is white with `drop-shadow-md` over the gradient (shell convention). RH/admin surface text is white on the translucent glass panels. **Identical scale to the approved Phase 11/12/13/14 contract — not re-derived.**

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / justificativa text / recommendation prose / candidate explanation reason / breakdown labels | 16px (`text-base`) | regular (400) | 1.5 |
| Label / status pill / etapa name / weight readout / age-band label / 4-5 ratio / char counter | 14px (`text-sm`) | semibold (600) | 1.4 |
| Card / panel title / "Decisão final" / "Breakdown por etapa" / "Comparativo de finalistas" / section heading | 20px (`text-xl`) | semibold (600) | 1.2 |
| Page heading (RH decision H1 / candidate explanation H1 / bias-audit H1) | 28px (`text-3xl`, responsive `md:text-4xl` cap) | semibold (600) | 1.2 |

**Notes:**
- The 14px/16px proximity is intentional and perceptually separated by **weight** (14 = semibold label, 16 = regular body), matching the approved Phase 11/12/13/14 contract — not a 14/15/16 micro-band.
- **The candidate explanation reason and the RH justificativa are load-bearing reading** — both render at **16px / line-height 1.5+** (`text-base leading-relaxed` where prose is long). Never compress the candidate-facing explanation below 16px, even if long; this is a transparency surface, not a dense data dump.
- The **consolidated score** is a large numeric readout (`text-3xl` / 28px, the display role) — the single hero number on the RH dashboard; it is an aggregate, not a verdict, and carries a neutral caption "Agregado ponderado — não re-pontuado".
- Only two weights: 400 (body, justificativa, recommendation, explanation reason, breakdown labels) and 600 (titles, labels, status pills, counters, CTAs, decision labels, age-band labels). No 500/700/800 despite availability. The `md:text-4xl` heading cap is a responsive variant on the top scale role (Phase 11/12/13/14 precedent), not a 5th semantic size.
- Uppercase micro-labels ("Recomendação", "Justificativa", "Limitação", "Faixa etária") use `text-xs font-semibold uppercase tracking-wide text-white/50` — a treatment of the 14px label role (small-caps eyebrow), not a new size (Phase 11/13/14 precedent).

## Color

The candidate explanation page is the **glass-over-gradient** persona surface. The RH dashboard and admin bias-audit are the **desktop brand panel** surface. Any score/recommendation signal lives **only** on the RH/admin side; the candidate sees a high-level result and a respectful reason — **never** a raw score, band, or color verdict (RNF-07a / LGPD-04). **Palette is LOCKED — identical to Phase 11/12/13/14.**

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#00109E` brand-primary (gradient on candidate via `BackgroundImage`; solid brand panel on RH/admin) | Full-page background behind all glass/panels |
| Secondary (30%) | `bg-white/5`–`bg-white/20` translucent white (Glass / GlassPanel / GlassCard) | Dashboard, breakdown table, decision form, recommendation block, candidate explanation card, bias-audit table, navbar |
| Accent (10%) | `#35BFAD` brand-accent (`--accent`) | See reserved list below |
| Destructive | `#EF4444` (`--destructive`) | The `rejeitado` decision-option selected-state tint + decision/revision confirm-dialog destructive framing + error / load-failed iconography ONLY |

**Accent (`#35BFAD`) reserved for — explicit list:**
1. The **`SugestaoIABadge`** accent tint (`border-[#35BFAD]/40 bg-[#35BFAD]/10`, `Sparkles`) on the **textual recommendation block ONLY** — the single "this came from advisory logic" signal on the RH dashboard. NOT on the consolidated score, NOT on the breakdown rows, NEVER candidate-facing.

Accent is NOT used for: the consolidated score number, the per-etapa breakdown rows, the `decisao` radio options, the RH decision CTA, the candidate "Solicitar revisão" CTA, the bias-audit table, links, generic hover, or the 4/5 ratio. The RH and candidate CTAs use glass-white (`bg-white/20` → `bg-white/30`). This keeps accent rare and reserved for the advisory-recommendation signal.

### RH/admin status & signal treatments (RH/admin-facing only)

These appear on the RH dashboard, the decision form, and the bias-audit view — never on a candidate surface:

- **Consolidated score** — large neutral numeric readout (`text-3xl text-white`), NO red/green tint. It is an aggregate, not a pass/fail; a caption reads "Agregado ponderado — não re-pontuado".
- **Per-etapa breakdown rows** — neutral structured presentation (`{score} / {max}` + weight %), `border-white/15 bg-white/5 text-white/70` badges (the `ScorecardAvaliacao` neutrality contract). Missing/unapplied etapas render a neutral **"N/A"** pill (`border-white/20 bg-white/5 text-white/60`) with a `tooltip` ("Etapa não aplicada — não pondera no agregado"). NO red/green tint on any score.
- **Decision option selected-state** — the `decisao` radio: `aprovado` selected → neutral glass-white reinforced state (`bg-white/20`, no green); `rejeitado` selected → destructive-tinted state (`border-red-400/30 bg-red-500/15 text-red-300`) to make the gravity visible at capture time; `em_espera` selected → neutral amber-informative (`border-amber-400/30 bg-amber-500/15 text-amber-300`), urgency-not-alarm (matches the Phase 14 24h-marker amber idiom). Unselected options are neutral glass.
- **Bias-audit 4/5 flag** — an age band whose adverse-impact ratio `< 0.8` renders a destructive-tinted row tint (`bg-red-500/15 text-red-300 border-red-400/30`) + a `tooltip` naming the rule ("Razão de selection-rate < 0,8 vs a faixa de maior taxa — regra 4/5 EEOC"). Bands `≥ 0.8` render neutral. The reference band (highest selection rate) renders neutral with a "referência" micro-label.

The candidate explanation **surface carries no** score, band, ratio, or color verdict — only the neutral glass card, a respectful reason, a high-level result line, and the revision CTA.
