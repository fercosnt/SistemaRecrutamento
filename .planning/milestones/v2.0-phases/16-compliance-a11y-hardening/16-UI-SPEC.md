## 2. Per-Screen A11y Acceptance Bar (WCAG 2.1 AA)

**Target for every in-scope screen:** axe-core scan with tags
`['wcag2a','wcag2aa','wcag21a','wcag21aa']` returns **zero `serious` or `critical`
violations** (operationalizes "axe-core ≥90"; `moderate`/`minor` are advisory and may
be tracked-excluded with a comment per the Phase-5 `.exclude()` precedent). The
acceptance bar = the union of these axe rule families plus the manual keyboard checks
axe cannot fully model:

| # | WCAG AA dimension | axe rule family / manual check | Pass criterion |
|---|-------------------|--------------------------------|----------------|
| AB-1 | Color contrast | `color-contrast` | All text ≥ 4.5:1 (≥ 3:1 for ≥18.66px bold / ≥24px). Covers amber-on-translucent, `text-white/50–60` micro-labels, Select placeholder. |
| AB-2 | Name / Role / Value | `aria-roles`, `aria-valid-attr-value`, `aria-required-attr`, `name-role-value` | Every custom-role widget (`role="radio"`, `role="tab"`, sliders) exposes correct role + state + accessible name. |
| AB-3 | ARIA composite semantics | `aria-required-children`, `aria-required-parent` | Tab groups = `tablist`/`tab`/`tabpanel`; radio groups = `radiogroup`/`radio`; not loose `aria-pressed` buttons. |
| AB-4 | Form labels | `label`, `label-title-only`, `select-name`, `aria-input-field-name` | Every input/select/textarea/slider has a programmatic label (not placeholder-only, not `title`-only). |
| AB-5 | Keyboard operability | manual (axe cannot test) + `tabindex`, `scrollable-region-focusable` | All controls reachable + operable by keyboard; custom radios/tabs support arrow-key roving focus; no pointer-only affordance. |
| AB-6 | Focus order & visible focus | manual + `:focus-visible` audit | Logical DOM tab order; visible focus ring on every interactive element on the glass surface. |
| AB-7 | Non-text / icon-only | `image-alt`, `button-name`, `link-name` | Icon-only controls have accessible names; decorative icons `aria-hidden="true"` (already the project norm). |
| AB-8 | Live status announce | manual + `aria-live` | Autosave status (`RedacaoEditorScreen`, candidate avaliação) announced via `aria-live="polite"`, not silent. |

**Verified-via-CI** = axe assertions for AB-1..AB-4, AB-7 (axe-modelable);
**verified-via-review/UAT** = AB-5, AB-6, AB-8 (keyboard + focus + live-region —
manual checks in the Phase-16 HUMAN-UAT runbook, since headless axe under-tests them).

## 4. CI Gate Contract (how axe-core ≥90 is enforced)

Consistent with the existing Playwright setup (`playwright.config.ts` chromium project,
`baseURL :3003`, webServer `npm run dev`) and the existing `.github/workflows/ci.yml`
`e2e` job (already runs `npx playwright test --project=chromium` unconditionally).

### 4a. Test harness — extend `e2e/a11y.spec.ts` (do NOT create a parallel file)

- **Keep** the existing public-route loop (Phase-5 gate, zero-violations) untouched.
- **Add** a main-M2-screens loop. Two tiers, mirroring the project's established
  `E2E_REAL_LOGIN` gating precedent (`prova-cognitiva.spec.ts`, `explicacao-flow.spec.ts`):

  **Tier-A (UNCONDITIONAL in CI — the blocking gate):** scan the in-scope screens
  that render meaningfully under a **mocked Supabase session** via `page.route()`
  (the same mocking pattern Tier-1 specs already use — no live secrets). Seed a
  candidate-role and an RH-role `storageState`/route-mock fixture under `e2e/fixtures/`
  so the role-gated shells render. For each screen:

  ```ts
  const results = await new AxeBuilder({ page })
    .withTags(['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa'])
    .analyze()
  const blocking = results.violations.filter(
    v => v.impact === 'serious' || v.impact === 'critical'
  )
  expect(blocking).toEqual([])   // operationalizes "axe-core >=90"
  ```

  Tracked false-positives / deferred-token nodes use the **same `.exclude(selector) +
  tracking-comment` mechanism** already sanctioned in `a11y.spec.ts` (e.g. the
  `DEFERRED_SELECT_PLACEHOLDER`, `OTP_TRANSPARENT_INPUT` precedent) — never disable a
  whole screen's assertion.

  **Tier-B (env-gated `E2E_REAL_LOGIN=1` — manual/UAT deeper sweep):** the screens
  whose data cannot be faithfully mocked (live `scores_candidato`, seeded candidatura
  in a specific etapa) get a real-login axe pass in the Phase-16 HUMAN-UAT runbook.
  These skip-with-reason in default CI (so `playwright test` stays green) — matching
  the existing `prova-cognitiva` / `explicacao-flow` gating. AB-5/AB-6/AB-8 (keyboard,
  focus, live-region) manual checks live here too.

### 4b. CI wiring

- **Fold into the existing `e2e` job** in `.github/workflows/ci.yml` — the a11y spec
  already runs inside `npx playwright test --project=chromium`. No new job required;
  the expanded `a11y.spec.ts` Tier-A assertions run as part of the current
  unconditional Playwright step. (A dedicated `a11y` job is acceptable if isolation is
  preferred, but the default is "extend the spec, the existing job picks it up.")
- The gate is **green when** every Tier-A in-scope screen yields zero serious/critical
  axe violations. CI goes red on any new serious/critical violation (same red-on-growth
  spirit as the existing tsc-baseline gate).
- Keep the Lighthouse job as-is (HARD-02 perf is deferred — §5).
