## Cross-Phase Issues

### BLOCKER 1 — Candidatura submit silent-fails after redirect-login (`INT-BLOCKER-1`)
- **Affects:** `CAND-01`, `CAND-02`, `CAND-03`, `VAGA-03`
- **Break:** `src/store/authStore.ts:284` `setSession()` does not call `fetchProfile()`. Only `initialize()` (App mount, single call site at `App.tsx:159`) populates `profile`/`candidato`. On the redirect-after-anonymous path (`/vagas/:slug` → `/auth/login?redirect=...` → login → form), the `SIGNED_IN` event fires `setSession`, leaving `candidato = null`.
- **Consequence:** `FormularioCandidaturaPage.tsx:233` guard `if (!cvFile || !user || !candidato || !vaga) return` returns silently — no toast, no error, user cannot submit.
- **Historical note:** Identified in `.planning/phases/01-foundation-saneada/KNOWN-ISSUES-CARRYOVER-PHASE-3.md:81` as "Option B" — never implemented.
- **Fix:** In `App.tsx` `onAuthStateChange`, call `initialize()` (not just `setSession`) on `SIGNED_IN`. Single edit closes BLOCKER 1 and BLOCKER 2.

### BLOCKER 2 — Profile data absent after any fresh login (`INT-BLOCKER-2`)
- **Affects:** `CAD-06`, `AUTH-01`, `PERF-01`, `PERF-02`
- **Same root cause as BLOCKER 1.** `tryAutoLogin` (cadastro) + every `/auth/login` signIn lands on `/candidato/perfil` with `candidato = null`. Personal fields empty; `useCandidaturas()` disabled (`enabled: !!candidato?.id`); only self-heals on full page reload.
- **Already foreshadowed in Phase 4 SUMMARY:** "plan checker autônomo passou com gates verdes mas página estava UNUSABLE end-to-end."
