## The One Real Gap — BLOCKER-01 (AVAL-03)

`supabase/functions/avaliar-redacao/index.ts:367-368`

```
const { default: Anthropic } = await import(["npm:", "@anthropic-ai/sdk@0.102.0"].join(""));
const { default: OpenAI }    = await import(["npm:", "openai@6.42.0"].join(""));
```

The SDKs are imported **only** dynamically, via string-concat, inside `Deno.serve`. No static top-level `npm:` import exists. The Supabase EF deploy bundler never sees the package specifier → `ERR_MODULE_NOT_FOUND` at runtime. Every candidate SJT open-case submission (`SjtCasoAbertoScreen` → `avaliacaoService.submitCasoAberto` → `invoke('avaliar-redacao')`) returns 500 in PROD.

This is the recurring `.join` import bug. The 6 later AI EFs (analise, comparativo, redacao-cultural, devolutiva-bigfive, guia-entrevista, transcricao-entrevista) were all migrated to static `npm:` imports and are PROD-green; `avaliar-redacao` is the one EF that was deployed before the fix pattern and never re-migrated. `avaliar-redacao-cultural`'s own header comment explicitly notes the bug is still present in the SJT EF.

**Fix (1 EF):** add static `import Anthropic from "npm:@anthropic-ai/sdk@0.102.0"` + OpenAI (+ zod helper) at the top of the file, drop the dynamic `await import(...)`, pass the clients into the handler, and redeploy `avaliar-redacao` JWT-on. This closes AVAL-03 and the only broken E2E flow.
