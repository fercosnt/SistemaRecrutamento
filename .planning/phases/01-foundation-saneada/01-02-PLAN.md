<objective>
Unify the two separate auth stores (authStore for candidatos, adminAuthStore for RH) into a single Zustand store with role awareness, and convert adminAuthStore into a backward-compatible re-export shim.

Purpose: The current dual-store architecture causes race conditions in onAuthStateChange, duplicated initialization logic, and inconsistent session handling. A single store with role derived from JWT app_metadata eliminates all these issues and enables the RoleGuard (Plan 03).

Output: A unified authStore.ts with role/profile fields and an adminAuthStore.ts that re-exports for RH page backward compatibility.
</objective>

```typescript
function extractRole(session: Session | null): Role | null {
  if (!session?.user) return null
  const role = session.user.app_metadata?.role
  if (role === 'candidato' || role === 'rh' || role === 'administrador') return role
  return null
}

async function fetchProfile(userId: string, role: Role | null): Promise<Record<string, unknown> | null> {
  if (role === 'rh' || role === 'administrador') {
    const { data } = await supabase
      .from('usuarios_rh')
      .select('*')
      .eq('user_id', userId)
      .eq('ativo', true)
      .is('deleted_at', null)
      .single()
    return data as Record<string, unknown> | null
  }
  const { data } = await supabase
    .from('candidatos')
    .select('*')
    .eq('user_id', userId)
    .single()
  return data as Record<string, unknown> | null
}
```

**Store implementation:**
- `clearAuth`: sets `{ user: null, session: null, role: null, profile: null, isAuthenticated: false }`
- `setSession(session)`: extracts role via `extractRole(session)`, sets `{ session, user: session?.user ?? null, role, isAuthenticated: !!session }`
- `initialize()`: calls `supabase.auth.getSession()`, if session exists -> `extractRole` + `fetchProfile`, else `clearAuth`. Always sets `isLoading: false` in finally block. Starts with `set({ isLoading: true })`.
- `logout()`: calls `supabase.auth.signOut()`, then `clearAuth()`
