# Phase 14 — UI Design Contract

> Visual and interaction contract for **Entrevistas com IA Companion (Etapas 4+5)**. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Two surfaces, two personas:**
> 1. **RH/gestor interview workspace** (desktop-first, internal admin persona, role-gated) at `/rh/candidato/:id/entrevista`. Three stacked zones on the existing `RHLayout` + `Glass` brand surface: (a) a **candidate dashboard** that surfaces the etapa, the manually-scheduled interview datetime, and a **"24h antes" marker** (in-app only — no email/calendar pipeline in V1); (b) an **AI-generated STAR/PEI interview guide** (5–7 perguntas com âncoras BARS 1–5 + dimensão, guaranteeing ≥1 pergunta for every dimension with score `<3`), each AI-derived block carrying the `SugestaoIABadge`; (c) an **inline-editable scorecard** where the gestor records `notas_humanas` per competência (BARS sliders + notes) — a direct analog of `RedacaoOverrideForm` / `ScorecardAvaliacao`. A separate **transcript-analysis review panel** lets RH paste a transcript → `avaliar-transcricao-entrevista` returns BARS scores + flags + citations; a **language/accent flag at score `<3` blocks `avancar_etapa()`** until a human confirms review (RNF-07a, anti-regional-bias — same philosophy as Phase 13 culture-fit style-neutralization).
> 2. **Candidate cognitive reasoning prova** (mobile-first, public glass-over-gradient persona), **opt-in only** via `vaga.aplica_cognitivo` (default `false`). One CC0 reasoning item at a time on the established SJT MC shell + **light proctoring**: a **soft count-up timer (no hard cutoff)**, **tab-blur / visibilitychange logging**, and **paste-block on the answer field**. The candidate **never** sees a score, a band, a threshold, or any pass/fail framing (RNF-07a). The qualitative band (5 faixas) is **RH-facing only**, always labeled **CONTEXTUAL / não-eliminatório**; rejection by cognitive alone requires an expanded justification + a `bias_audit_log` row.
>
> **Binding spec:** `docs/prds/m2-funil-rh/PRD-MASTER-funil-rh-m2.md` (interview sections: STAR/PEI guide, dashboard, transcript analysis) + `docs/prds/m2-funil-rh/PRD-cognitivo-raciocinio.md` (ENTREV-05 — CC0 items, qualitative band, CONTEXTUAL, bias_audit_log); consult `docs/prds/prd-db-004-entrevistas-avaliacoes.md` (prior). Covers ENTREV-01..05. Out of scope: final consolidated decision (Phase 15), WCAG/a11y hardening (Phase 16), auto-scheduling/calendar (Future).

## Spacing Scale

Declared values (multiples of 4; matches the existing glass + RH shell which scored 4/4 on spacing in Phase 11/12/13 — `space-y-4/5/6/8`, `gap-2/3/4`, `p-6`, `py-20`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside badges / status pills / flag chips (`gap-1`) |
| sm | 8px | Compact element spacing, slider-to-value gaps, radio inner padding, dashboard meta rows (`gap-2`) |
| md | 16px | Default gap between form blocks, guide question rows, BARS dimension rows, sidebar list items (`space-y-4`, `gap-4`) |
| lg | 24px | Card / panel inner padding (`p-6`), gap between the dashboard / guia / transcrição / scorecard zones (`space-y-6`) |
| xl | 32px | Container vertical rhythm between major panels (`space-y-8`) |
| 2xl | 48px | Header-to-content break; empty / not-scheduled / all-done state vertical padding (`p-12`) |
| 3xl | 64px | Candidate prova top/bottom breathing room (`py-20` from the SJT shell) |

**Exceptions:** Touch targets on the **candidate** cognitive prova (primary CTA, Voltar/Avançar nav, option labels) carry the established `min-h-[44px]` mobile a11y floor (44 = 4×11, on-scale but outside the named set — inherited from Phase 11). On the **RH desktop** side, slider thumbs (`size-4` = 16px, on-scale) are mouse targets and do not require the 44px floor, but RH action buttons (Salvar notas, Salvar revisão, Confirmar avanço, tab buttons) carry `min-h-[44px]` for consistency with the Phase 13 RH panel.

## Typography

Family: Helvetica Neue (`--font-family`). Exactly 4 sizes, 2 weights. Body line-height 1.5, heading line-height 1.2. Candidate surface text is white with `drop-shadow-md` over the gradient (shell convention). RH surface text is white on the translucent glass panels.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / transcript box / guide question text / notes / cognitive scenario / reasoning | 16px (`text-base`) | regular (400) | 1.5 |
| Label / counter / status pill / band label / slider value / dashboard meta / citation | 14px (`text-sm`) | semibold (600) | 1.4 |
| Card / panel title / competência name / guide section heading / dimension name | 20px (`text-xl`) | semibold (600) | 1.2 |
| Page heading (RH workspace H1 / candidate prova H1) | 28px (`text-3xl`, responsive `md:text-4xl` cap) | semibold (600) | 1.2 |

**Notes:**
- The 14px/16px proximity is intentional and perceptually separated by **weight** (14 = semibold label, 16 = regular body), matching the approved Phase 11/12/13 contract — not a 14/15/16 micro-band.
- **Transcript reading on the RH side is load-bearing** (analogous to Phase 13 essay reading): the pasted transcript and AI citations render at **16px / line-height 1.6+** for careful review — use `text-base leading-relaxed` (≈16px/1.625) minimum; never compress transcript text below 16px even when long.
- The cognitive prova scenario body is 16px at 1.5 — comfortable reading on mobile, never smaller.
- Only two weights: 400 (body, transcript, guide question text, notes, scenario, reasoning) and 600 (titles, labels, band labels, counters, CTAs, decision labels). No 500/700/800 despite availability. The `md:text-4xl` heading cap is a responsive variant on the top scale role (Phase 11/12/13 precedent), not a 5th semantic size.
- Uppercase micro-labels ("Citações", "Red flags", "Raciocínio", "Bandeiras") use `text-xs font-semibold uppercase tracking-wide text-white/50` — a treatment of the 14px label role (small-caps eyebrow), not a new size (Phase 11/13 precedent).

## Color

The candidate cognitive prova is the **glass-over-gradient** persona surface (translucent white over the brand gradient). The RH side is the **desktop brand panel** surface. Any pass/fail / band signal lives **only** on the RH side and is **always** framed as CONTEXTUAL/suggestion (RNF-07a).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#00109E` brand-primary (gradient on candidate via `BackgroundImage`; solid brand panel on RH) | Full-page background behind all glass/panels |
| Secondary (30%) | `bg-white/5`–`bg-white/20` translucent white (Glass / GlassPanel / GlassCard) | Dashboard, guide, scorecard, transcript box, navbar, option cards, status pills |
| Accent (10%) | `#35BFAD` brand-accent (`--accent`) | See reserved list below |
| Destructive | `#EF4444` (`--destructive`) | "Bloquear avanço" / flag-confirm affordance + error / load-failed iconography ONLY |

**Accent (`#35BFAD`) reserved for — explicit list:**
1. The RH **`SugestaoIABadge`** accent tint (`border-[#35BFAD]/40 bg-[#35BFAD]/10`, `Sparkles`) on every AI-derived block — the STAR/PEI guide header, each transcript-analysis BARS dimension, the cognitive RH band summary. RH panel only, never candidate-facing.
2. The candidate **"Salvo automaticamente"** autosave affordance (`Check` icon + text tint), if the cognitive prova carries autosave — the single accent touchpoint while the candidate works.

Accent is NOT used for: the candidate primary CTA, the RH action buttons, slider fills, links, generic hover, the 24h marker, the cognitive band, or any score value. The candidate CTA and RH buttons use glass-white (`bg-white/20` → `bg-white/30`). This keeps accent rare and reserved for the "this came from AI" signal.

### RH interview status / flag signals (RH-facing only)

These appear on the dashboard, the transcript-analysis panel, and the cognitive band — never on a candidate surface:

- **24h marker (dashboard)** — informative urgency cue, NOT alarm. Within 24h of the scheduled datetime → `bg-amber-500/15 text-amber-300 border-amber-400/30` pill ("Entrevista em <24h"); ≥24h away or unscheduled → neutral `border-white/20 bg-white/5 text-white/80`. A `tooltip` names the exact scheduled datetime.
- **Transcript BARS dimensions** — neutral structured presentation (`x / 5`), NO red/green pass-fail tint on the score itself (mirrors `ScorecardAvaliacao` neutrality). Each dimension carries `SugestaoIABadge variant="compact"`.
- **Language/accent flag (anti-regional-bias)** at score `<3` → a `destructive`-tinted alert block (`bg-red-500/15 text-red-300 border-red-400/30`) that **blocks `avancar_etapa()`**: the "Avançar etapa" CTA is `disabled` and a `RevisaoHumanaMarker` + tooltip names the firing rule ("Bandeira de linguagem/sotaque em score <3 — revisão humana obrigatória antes de avançar"). The block clears only after a human confirms review.
- **Cognitive qualitative band (5 faixas, RH-only)** — rendered with the reused **"Contextual · não-eliminatório"** badge (`border-white/15 bg-white/5 text-white/70`), neutral text, NO red/green tint on the band itself. The band label is descriptive (e.g. "Banda 3 de 5 — mediana"); a `tooltip` states "Contextual — nunca elimina sozinho. Decisão sempre humana." Rejection by cognitive alone forces the expanded-justification + `bias_audit_log` path (see Copywriting).

The cognitive prova **candidate** surface carries **no** band, score, or color verdict — only neutral progress and a neutral "Resposta registrada" acknowledgment.
