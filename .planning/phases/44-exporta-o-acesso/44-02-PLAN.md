Mesmo cabeçalho de protocolo da Task 1, com o acréscimo que importa: **este arquivo TEM corpo `$$`**
(as duas RPCs são `LANGUAGE plpgsql`) cercado de `REVOKE`/`GRANT`/`COMMENT` — é exatamente a

**A tabela:**

```
public.solicitacoes_dados
  id            uuid        PRIMARY KEY DEFAULT gen_random_uuid()
  candidato_id  uuid        NOT NULL REFERENCES public.candidatos(id)
  tipo          text        NOT NULL DEFAULT 'acesso' CHECK (tipo IN ('acesso','exclusao'))
  situacao      text        NOT NULL DEFAULT 'pendente' CHECK (situacao IN ('atendido','pendente'))
  causa         text        NULL CHECK (causa IS NULL OR causa IN ('falha_geracao','curriculo_ausente','permissao'))
  solicitado_em timestamptz NOT NULL DEFAULT now()
  atendido_em   timestamptz NULL
```

Quatro pontos que não são discricionários:

- **`tipo` nasce com dois valores no CHECK e um em uso.** A Phase 45 é a fase de maior risco do
  milestone e não pode gastar orçamento de risco com migration de retrofit sobre linhas vivas. O
  `COMMENT ON COLUMN tipo` registra isso, junto com a decisão de a fila desta fase filtrar
  `tipo = 'acesso'` **no servidor**.
- **`ON DELETE` da FK é decisão da Phase 45, não desta.** Deixe a FK sem cláusula (= NO ACTION) e
  escreva no `COMMENT ON CONSTRAINT` que a Phase 45 é quem sabe se o pedido de acesso sobrevive ao
  tombstone. Escolher agora é decidir por uma fase que ainda não leu o próprio problema.
- **`solicitado_em` é o marco do Art. 19, II** — é dele que o cooldown lê e é dele que o SC#4 conta.
  Diga isso no `COMMENT ON COLUMN`.
- **Os três tokens de `causa` vêm verbatim da §Coluna "O que aconteceu" da 44-UI-SPEC.** O cliente
  traduz com fallback total; o CHECK fecha o vocabulário no banco. Divergência entre os dois produz
  célula em branco na fila — a assunção A5 da pesquisa.

**Índice do cooldown:** `CREATE INDEX idx_solicitacoes_dados_cooldown ON public.solicitacoes_dados
(candidato_id, solicitado_em DESC);` — a leitura do cooldown roda em todo carregamento da seção 3
do painel do candidato **e** em toda invocação da EF.

**RLS:** `ENABLE ROW LEVEL SECURITY` e **uma única policy**, de SELECT, own-row para o candidato,
espelhando o predicado vivo de `candidato_le_propria_candidatura`
(`candidato_id IN (SELECT id FROM public.candidatos WHERE user_id = (select auth.uid()))`).
**Nenhuma policy de INSERT, UPDATE ou DELETE para o candidato.** O `COMMENT` tem de carregar a
razão, porque ela não é óbvia: se o candidato pudesse inserir, ele poderia **não** inserir — furando
o cooldown — ou inserir já `atendido` sem que nada tenha sido entregue. O registro é afirmação do
servidor sobre um fato do servidor; a escrita é da EF com `service_role`, que bypassa RLS.
O RH **não** lê esta tabela por policy: lê pelas RPCs, porque o nome do candidato vive em
`candidatos` e o escopo do BD-8 é predicado explícito.

**As duas RPCs, `SECURITY DEFINER` com `SET search_path = ''` e referências totalmente
qualificadas.** O predicado de escopo do BD-8 é escrito **uma vez, em prosa idêntica nas duas**, e o
`COMMENT` de cada uma declara o invariante: *fila e contador usam o MESMO predicado; se divergirem,
o badge conta o que a tela não mostra* — e aqui esse trabalho tem prazo de 15 dias.

Predicado (tradução do BD-8; o análogo da P42 não serve porque um pedido de acesso **não tem vaga**):

```
v_role = 'administrador'
OR (v_role = 'rh' AND EXISTS (
      SELECT 1 FROM public.candidaturas cd
       WHERE cd.candidato_id = s.candidato_id
         AND cd.deleted_at IS NULL
         AND cd.is_rascunho = false
         AND cd.vaga_id IN (SELECT vg.id FROM public.vagas vg WHERE vg.created_by = v_uid)))
```

O administrador vê **inclusive os órfãos** (pedido de candidato sem candidatura nenhuma) — e o
`COMMENT` diz por quê: o órfão é justamente o pedido que consome prazo legal sem ter dono natural, e
o admin é o dono. ⚠ Confirme os nomes vivos `deleted_at`/`is_rascunho`/`created_by` contra o
predicado da P42 antes de escrever; se algum não existir em `candidaturas`, **pare e registre** em
vez de adaptar por analogia.

1. **`public.listar_pedidos_dados(p_incluir_atendidos boolean DEFAULT true)`** —
   `RETURNS TABLE (id uuid, candidato_id uuid, candidato_nome text, situacao text, causa text,
   solicitado_em timestamptz, atendido_em timestamptz)`, `STABLE`. Guard de papel **NULL-safe**:
   `IF v_role IS DISTINCT FROM 'administrador' AND v_role IS DISTINCT FROM 'rh' THEN RAISE … USING
   ERRCODE = '42501'`. Nunca o idioma `NOT IN`, que com `v_role` NULL avalia NULL, não toma o `IF` e
   **falha ABERTO** — defeito real medido na 42-06. `LEFT JOIN public.candidatos` para resolver o
   nome no servidor (NULL quando não resolvível: a UI mostra "Não identificado", e o tipo da linha
   é escrito à mão no cliente justamente por isso). Filtro fixo `s.tipo = 'acesso'`. Quando
   `p_incluir_atendidos` for false, só `situacao = 'pendente'`.
   **Ordenação composta**, e ela é o que torna o aviso de corte verdadeiro:
   `ORDER BY (s.situacao = 'atendido'), CASE WHEN s.situacao = 'pendente' THEN s.solicitado_em END ASC,
   CASE WHEN s.situacao = 'atendido' THEN s.solicitado_em END DESC` — não atendidos primeiro do mais
   antigo ao mais recente, depois atendidos do mais recente ao mais antigo. `LIMIT 200`. O `COMMENT`
   registra que **mudar esta ordenação sem mudar a copy do aviso de corte faz a fila mentir por
   omissão**.
   ⚠ Devolva **apenas** as sete colunas nomeadas. Nada de e-mail, CPF, documento ou caminho de
   Storage: a fila é sobre o *pedido*, não sobre o *dado* (Invariante 5 da UI-SPEC).

2. **`public.contar_pedidos_dados_pendentes()`** — `RETURNS integer`, `STABLE`. Mesmo guard, mesmo
   predicado de escopo, mesmo filtro `tipo = 'acesso'`, contando `situacao = 'pendente'`. Sem
   `LIMIT`.

Para as duas: `REVOKE ALL ON FUNCTION … FROM PUBLIC, anon, authenticated;` e **só então**
`GRANT EXECUTE … TO authenticated;`. O `REVOKE … FROM PUBLIC` sozinho **não basta** — o
`pg_default_acl` do schema `public` concede EXECUTE a `anon` em todo `CREATE FUNCTION` como grant
direto e nomeado, e o idioma usado em quase toda migration do repositório remove um grant de
`PUBLIC` que nunca existiu, deixando `anon=X` de pé. Revogue de `anon` nominalmente.
