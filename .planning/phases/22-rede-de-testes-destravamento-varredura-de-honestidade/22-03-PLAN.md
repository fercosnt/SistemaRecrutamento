<objective>
Make the candidate-facing auth flow honest and hack-free: enable the login submit buttons by default (validate-on-submit, drop the `!isValid` gate that forced the E2E `blur()` hack), propagate `?redirect` safely through login→cadastro→post-login using the ONE shared anti-open-redirect guard, and clear the orphan `candidatura_vaga_id` localStorage key on successful login.

Purpose: The `disabled={!isValid}` pattern is the origin of the `blur()` E2E hack (see [[reference_e2e_login_helper_onblur]]); `handleSubmit` already blocks invalid submits and renders `role="alert"` errors, so the gate is pure friction. `?redirect` must never become an open-redirect — reuse `resolveRedirect`, don't duplicate it (mirrors the CI-06 dedup lesson).
Output: shared `resolveRedirect` util + its test; both login pages enabled-by-default; `?redirect` threaded and guarded; orphan key cleared.
</objective>

| T-22-03-02 | Tampering | `react-router@6.30.1` HIGH open-redirect CVE (protocol-relative reinterpretation) | accept | App-level `resolveRedirect` mitigates this param; router bump ≥6.30.3 is out of Phase-22 scope — flagged for Phase 24/27 |
