# Phase 17 — UI Design Contract

> Visual and interaction contract for **Navegação & Arquitetura de Informação** (standalone mini-fase, fora de milestone). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This is a navigation-wiring + IA + legacy-cleanup phase over what M2 already shipped. The Beauty Smile design system is **established and LOCKED** — this contract REFERENCES it, it does not redefine it. The contract is prescriptive ONLY for the genuinely-new / substantially-rewritten surfaces (RH candidate hub, 404, Dashboard/Perfil split, admin sidebar entry, LGPD card) and the **shared step-guided interaction model** (`funilNavMap`, D-17). Already-shipped M2 workspaces (entrevista/redação/decisão) are being WIRED IN, not redesigned — only their navigation/entry contract is specified here.

### Persona shells (MATCH, do not reinvent — D-27 precedent)
- **Candidate shell** (Dashboard, Perfil, hub-adjacent): `BackgroundImage` + `BeautySmileLogo` + `CandidatoNavbar` (sticky navbar w/ avatar + logout `GlassButton`) + `GlassCard` wrappers. Canonical reference: `src/components/pages/MeuPerfilCandidatoPage.tsx`.
- **RH shell** (candidate hub at `/rh/candidatos/:id`, workspaces): existing `RHSidebar` (`src/components/RHSidebar.tsx`) + glass content panels. The hub lives inside the RH sidebar shell.
- **404 page**: standalone glass surface on `BackgroundImage` (no persona navbar — it must render for any/unknown role). Role-aware back-link only.

### Accessibility carry-forward (icon-only controls — Dimension 2 advisory resolved)
- The net-new **"Admin"** sidebar item carries a visible text label ("Admin") — no icon-only net-new action is introduced.
- **Pre-existing icon-only controls** reused by this phase (sidebar collapse `ChevronLeft/Right`, logout, mobile-nav toggle) MUST retain their existing `aria-label` / accessible-name attributes unchanged — **no regression**. If a reused control lacks an `aria-label`, the executor adds one (e.g. `aria-label="Recolher menu"`, `aria-label="Sair"`, `aria-label="Abrir menu"`).
- The **404 back-link** is text-labeled (role-aware copy below), so it needs no icon-only fallback.

### Broken-token caveat (M2, LOCKED workaround — D-26)
- `bg-primary` is **broken project-wide** (tailwind.config expects HSL components; globals.css defines HEX → `hsl(#00109E)` invalid). **Do NOT use `bg-primary`.** Use the established hex-literal workaround `bg-[#00109E]` (precedent: `LoginCandidatoPage`, Phase 4 carryover-B). The glass primitives use `bg-brand-primary/NN` and `bg-white/NN` which are valid — prefer those for glass surfaces.

## Spacing Scale

LOCKED by Beauty Smile design system (base unit **4px**; every value a multiple of 4). Use Tailwind numeric classes (`p-4`, `gap-6`, etc.).

| Token | Value | Usage this phase |
|-------|-------|------------------|
| xs | 4px | Icon-to-text gaps (`iconGap`), inline badge padding |
| sm | 8px | Compact gaps (list rows, badge clusters) |
| md | 16px | Default element spacing, grid gutter |
| lg | 24px | **Card internal padding** (`GlassCard` default `p-6`), section padding |
| xl | 32px | Layout gaps between hub sections, `GlassPanel` padding (`p-8`) |
| 2xl | 48px | Major section breaks (hub stage groups), empty-state vertical breathing |
| 3xl | 64px | Page-level vertical rhythm (`py-16` section spacing) |

**Exceptions:** Touch targets for icon-only controls (sidebar collapse, logout, mobile nav, 404 back-link) must be ≥ **44px** (`min-h-11 min-w-11`) for tap accessibility — 44 is on-scale (token `11`). No other exceptions.

## Typography

LOCKED by Beauty Smile design system. Exactly the four sizes and **two weights** below are used across the new/rewritten surfaces.

| Role | Size | Weight | Line Height | Font | Used for |
|------|------|--------|-------------|------|----------|
| Body | 16px | 400 (regular) | 1.5 (24px) | Inter | Section copy, candidatura rows, empty-state body, LGPD card body, 404 body |
| Label | 14px | 600 (semibold) | 1.43 (20px) | Inter | Badges (etapa/status), CTA button text, field labels, stage chips |
| Heading | 24px (H4) | 600 (semibold) | 1.33 (32px) | Montserrat | Hub section headings, Dashboard section titles, empty-state headings, card titles |
| Display | 48px (H1) | 600 (semibold) | 1.0 | Montserrat | 404 page title / "404" numeral; hub candidate name header |

**Two weights only: 400 (regular) + 600 (semibold).** Bold (700) is NOT used on these surfaces — the 404 display numeral uses 600 semibold at 48px (the size + Montserrat carry the visual weight; no bold needed). **Body line-height 1.5 and heading line-height ≈1.2–1.33 are LOCKED** (matches the M2 Big Five legibility fix). Do not introduce font sizes outside {14, 16, 24, 48} on these surfaces (the design system also defines 12/18/20/30/36 — keep this phase to the four roles above to stay scannable).

## Color

LOCKED by Beauty Smile design system. The new surfaces sit on the **public/candidate glass theme** (turquoise→deep-blue gradient via `BackgroundImage`) for the candidate persona, and the **RH glass content theme** for the RH hub. 60/30/10 split below.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `BackgroundImage` gradient `#35BFAD → #00109E` (candidate) / app background (RH) | Page background / surface field behind glass |
| Secondary (30%) | Glass surfaces — `bg-white/15` (light glass, `GlassCard` default) / `bg-black/30` (dark glass for legibility) | Cards, hub section panels, sidebar, LGPD card, 404 panel |
| Accent (10%) | Turquoise `#35BFAD` (`text-accent` / `bg-brand-accent`) | **Reserved-for list below** |
| Destructive | Error red `#EF4444` (`text-error` / `bg-error`) | Destructive/terminal-state signaling ONLY (see Destructive section) |

**Accent (turquoise) reserved for — explicit list, never "all interactive elements":**
1. The **primary step-guided CTA** (the single dominant "próximo passo" button) on the candidate Dashboard and the RH hub.
2. The **active/current-stage indicator** in the hub's stage timeline (the `etapa_atual` chip).
3. The **LGPD card CTA** ("Ver explicação").
4. The **404 back-link** primary affordance.
Everything else interactive uses neutral glass affordances (`GlassButton` default, white/80 text links) — accent stays scarce so "próximo passo" reads as dominant (D-06).

**Semantic status colors (NOT counted in the 10% accent budget — they are data encoding, reused from M2):** stage/status badges keep the existing M2 mapping — `aguardando_resposta` blue, `em_analise` warning/yellow, `aprovado` success green, `rejeitado` error red. The hub and Dashboard reuse `ETAPA_M2_LABELS` + the existing status-badge palette; do NOT invent new status colors.

**Contrast (HARD requirement — WCAG AA):** All text on glass must meet AA (turquoise-on-glass ≥ 4.5:1; the M2 Big Five fix darkened glass to `#00109E/85` to hit it). New glass surfaces with body text must use a dark-enough glass (`bg-black/30` or the `#00109E/85` precedent) so white/turquoise text passes AA. Light glass (`bg-white/15`) is acceptable only behind large/bold headings, not 14–16px body, unless verified ≥ 4.5:1.

## Interaction Contract — Shared Step-Guided Model (D-06 / D-09 / D-17)

This is the load-bearing interaction spec for the phase. Both personas consume the **single source of truth** `src/lib/navegacao/funilNavMap.ts`, which reuses `EtapaFunilM2` + `ETAPA_M2_LABELS` from `src/features/triagem/services/triagemService.ts` (do NOT create a parallel enum).

**`funilNavMap` shape (contract for the executor):** `Record<EtapaFunilM2, { label, rotaCandidato, rotaWorkspaceRH, ctaCandidato, ctaRH }>` keyed by the 8 enum values: `inscricao · triagem · avaliacao_assincrona · entrevista_online · entrevista_presencial · decisao_final · aprovado · rejeitado`.

**Visual dominance rule (D-06):**
- **Current stage** (`etapa_atual`): its "próximo passo" CTA is the single **accent (turquoise)** dominant button on the surface. Exactly one dominant CTA per view.
- **Passed stages**: accessible via neutral secondary affordances ("Revisar {label}") — present, not hidden, not accent.
- **Future stages**: render as **empty/locked state** ("Etapa ainda não iniciada") — they do NOT disappear (the funnel timeline is always fully visible so the user sees the whole pipeline).

**RH candidate hub sections (D-07 — "bem completo", each service-backed OR empty state):** Identidade do candidato (header w/ name + etapa chip) · Score de Triagem (IA) · Avaliação Assíncrona (Work-Sample/SJT + Big Five) · Avaliação Cognitiva · Redação · Entrevista · Decisão Final. Each section reads its real `features/*` service; never hardcoded mock data (the sin of the 1864-line mock being replaced).

**Route normalization (D-08):** standardize `/rh/candidatos/:id` (plural, hub) vs `/rh/candidato/:id/*` (singular, workspaces) to one pattern + redirects from old routes (no broken links). The link `TriagemTable nome → /rh/candidatos/:id` (line 325) stays; only the destination CONTENT changes (mock → real hub).

**Admin sidebar entry (D-13):** new **"Admin"** item in the existing `RHSidebar`, role-gated `administrador` only, opening sub-nav to `/admin/{ai-logs,prompt-versions,ai-costs,bias-audit}`. Reuse the sidebar's existing item/icon pattern (Lucide icon + visible label + active-state detection via `location.pathname`). Suggested icon: `ShieldCheck` or `Sliders` (Lucide), consistent with existing 24px sidebar icons. The item carries a visible "Admin" text label (no icon-only affordance).
