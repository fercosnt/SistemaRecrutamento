## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | icon↔label gaps inside chips/badges (`gap-1`) |
| sm | 8px | compact inline spacing, badge padding (`gap-2`, `px-2 py-0.5`) |
| md | 16px | default control/cell padding, dialog field gap (`p-4`, `gap-4`, `space-y-4`) |
| lg | 24px | page section rhythm (`space-y-6`), card padding (`p-6`) |
| xl | 32px | major block separation (`space-y-8`) |
| 2xl | 48px | empty/error vertical breathing (`py-12`) |
| 3xl | 64px | not used at page scale here |

**Page frame:** inherit `RHLayout` `<main className="p-4 lg:p-6">`; page root uses `space-y-6` (header → roster). Do not re-pad with an extra `p-8` wrapper (the legacy empty-state's `p-8` is dropped when the shell already pads).

**Exceptions:** interactive controls (primary button, dropdown trigger, dialog/alert-dialog action buttons, retry) carry `min-h-[44px]` touch/click targets (44 = 4×11, still on-grid). This is the established RH accessibility floor (Phase 16).

## Color

RH admin **60 / 30 / 10** split (deep-blue dominant, glass-white secondary, turquoise accent):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Deep blue `#00109E` (`BackgroundImage darkBlue`) | Full-page field behind the glass |
| Secondary (30%) | Glass white `bg-white/10–15` + `#2D2E30` sidebar | Roster card, table surface, dialogs, sidebar/topbar |
| Accent (10%) | Turquoise `#35BFAD` | **RESERVED — see list below** |
| Destructive | `#EF4444` (`--destructive`) via red tints | Deactivate confirm button, LAST_ADMIN toast, destructive AlertDialog action |

**Accent (`#35BFAD`) reserved for — and ONLY for:**
1. The primary CTA **"Novo usuário"** button.
2. The primary submit button inside the create/edit dialogs (`bg-primary` deep-blue OR turquoise — use shadcn `Button` default `bg-primary`; reserve raw turquoise for the CTA + focus).
3. Focus rings / keyboard-focus outline (`--ring` / turquoise focus-visible).
4. The **"Administrador"** role badge tint.
5. Selected/active affordances (e.g. active dropdown item hover echoes the `#35BFAD` used in `TriagemTable`).

Accent is NOT used for body text, generic borders, or non-primary buttons — those stay white/opacity neutrals. This keeps the 10% ceiling honest (gsd-ui-checker Dimension 3).

**Status/semantic tints (AA-verified combos, established Phase 16 — reuse verbatim, do not invent new alpha pairs):**

| Meaning | Classes |
|---------|---------|
| Ativo (positive) | `bg-green-500/20 text-green-300 border-green-500/30` |
| Inativo (muted, NOT alarming) | `bg-white/10 text-white/50 border-white/20` |
| Aguardando 1º acesso (attention) | `bg-amber-500/15 text-amber-100 border-amber-400/30` |
| Administrador (accent role) | `bg-[#35BFAD]/20 text-white border-[#35BFAD]/40` |
| Recrutador (neutral role) | `bg-white/10 text-white/80 border-white/20` |
| Destructive emphasis (last-admin / deactivate) | `bg-red-500/15 text-red-300 border-red-400/30` |

> Contrast rule (AA gate): keep white or the lightened `*-300` / `amber-100` text families on `/15–/20` tints over the dark-blue field — these are the pairs Phase 16 bumped to pass axe-core Tier-A. Never place `#35BFAD` as *text* on a translucent light fill (fails AA); turquoise is a fill/border/focus color here, white is its text.

## Create User Dialog ("Novo usuário")

**Trigger:** header CTA. **Container:** shadcn `Dialog` (modal, Radix — focus-trapped, Esc-closable). Title `text-xl font-semibold`. RHF + Zod (`email`, `nome_completo`, `cargo`, `papel ∈ {recrutador, administrador}`).

**Field layout** (single column, `space-y-4`, `Form` + `FormField`/`FormItem`/`FormLabel`/`FormControl`/`FormMessage`):

| Field | Control | Label / placeholder | Validation display |
|-------|---------|---------------------|--------------------|
| E-mail | `Input type="email"` | "E-mail" / "nome@beautysmile.com.br" | `FormMessage` below field; server `EMAIL_EXISTS` → set field error on `email` |
| Nome completo | `Input` | "Nome completo" | required, `FormMessage` |
| Cargo | `Input` | "Cargo" / "ex.: Analista de RH" | required, `FormMessage` |
| Papel | `Select` | "Papel" → items **"Recrutador"**, **"Administrador"** | default `recrutador`; `FormMessage` |

**Honest helper** (below fields, `text-xs text-white/60`): **"O usuário receberá um e-mail para definir a própria senha e acessar o painel."** — reflects exactly what the EF does (`resetPasswordForEmail → /auth/redefinir-senha?tipo=rh`); promise nothing more.

**Footer (`DialogFooter`):** secondary **"Cancelar"** (closes, no side effect) + primary **"Criar usuário"** (`min-h-[44px]`). While the mutation is pending: submit shows `Loader2` spinner + label **"Criando…"** and is disabled; Cancel stays enabled (or disabled — discretion) but no double-submit. Field-level validation blocks submit before invoke.

**Feedback (`error_code` → sonner toast, pt-BR — from CONTEXT decision):**

| Outcome | Toast / display |
|---------|-----------------|
| success | `toast.success` **"Usuário criado. Enviamos um e-mail para {email} definir a senha."** + close dialog + invalidate roster query |
| `EMAIL_SEND_FAILED` (**success-with-warning, NOT error**) | `toast.warning`/success-with-note **"Usuário criado, mas o e-mail de senha não pôde ser enviado. Use 'Resetar senha' na linha do usuário para reenviar."** + close + invalidate |
| `EMAIL_EXISTS` | keep dialog open; **field error on `email`: "Já existe um usuário com este e-mail."** |
| `VALIDATION` | keep open; generic `toast.error` **"Verifique os campos e tente novamente."** |
| `FORBIDDEN` | `toast.error` **"Você não tem permissão para esta ação."** |
| `LAST_ADMIN` | (not reachable on create) — n/a |
| `SERVER_ERROR` / unknown | `toast.error` **"Não foi possível concluir agora. Tente novamente em instantes."** |
| `NOT_FOUND` | `toast.error` **"Usuário não encontrado."** |

## Row Actions (DropdownMenu per row)

Trigger = `MoreHorizontal` icon button (`aria-label="Ações"`). Menu items, in order:

1. **"Editar papel"** — opens a small `Dialog` (title "Editar papel") with a single `Select` {Recrutador, Administrador} pre-set to the current role + footer **"Cancelar" / "Salvar papel"**. On save → invoke `mudar_papel` → toast + invalidate. (Inline-select-with-confirm is an allowed alternative per CONTEXT discretion.)
2. **"Ativar"** (when `ativo=false`) — **direct action, no confirm** (non-destructive) → invoke `ativar` → `toast.success` **"Usuário reativado."** + invalidate.
   **"Desativar"** (when `ativo=true`) — behind **AlertDialog** (see below).
3. **"Resetar senha"** — behind **AlertDialog** (see below).

Menu item styling follows vendored `DropdownMenuItem`; destructive items (Desativar) may carry `text-red-300`/`text-destructive` emphasis. Every item is keyboard-navigable (Radix roving focus) — no bare `onClick` divs.

### AlertDialog confirmations (honest pt-BR — CONTEXT locked)

**Desativar** — title **"Desativar usuário?"**, body **"{nome} perderá o acesso ao painel imediatamente. Você pode reativar depois."** Actions: `AlertDialogCancel` **"Cancelar"** + `AlertDialogAction` **"Desativar"** (destructive/red). Pending → **"Desativando…"** + disabled. Success → `toast.success` **"Usuário desativado."** + invalidate.

**Resetar senha** — title **"Enviar e-mail de redefinição de senha?"**, body **"Enviaremos um e-mail para {email} redefinir a senha. A senha atual continua válida até o usuário definir uma nova."** (do NOT claim the account is locked or the password is already changed — the EF only dispatches the email). Actions: **"Cancelar"** + **"Enviar e-mail"**. Pending → **"Enviando…"**. Success → `toast.success` **"E-mail de redefinição enviado para {email}."**

## Anti-Lockout UX (last active administrador)

Client-side derives `activeAdminCount` from the loaded roster. On the row of the **last active administrador**:
- **"Desativar"** menu item → **disabled** + `Tooltip`.
- **"Editar papel"** → the Administrador→Recrutador (rebaixar) path is blocked: either disable the "Salvar papel" action when it would demote the last admin, or disable the "Editar papel" item with the same tooltip.
- **Tooltip copy:** **"Não é possível desativar ou rebaixar o último administrador ativo."**
- The disabled trigger must be a real focusable element wrapped so the tooltip is keyboard-reachable (reuse the `TriagemTable`/`BiasAuditPage` `<span className="inline-flex"><button …/></span>` tooltip idiom — Radix wires `aria-describedby` on focus; no pointer-only affordance).

**Server is authoritative:** the hint is UX only. If a race defeats it, the EF returns `LAST_ADMIN` → `toast.error` **"Não é possível remover o último administrador ativo do sistema."** (no field routing — it is a global invariant). Self-row destructive actions fall under the same trap; the current admin's own row is not special-cased in the UI beyond the "(você)" marker.

## States Contract

Priority order (binding, via `AsyncState`): **loading → error → empty → success**.

| State | Render | Copy |
|-------|--------|------|
| Loading | `AsyncState` skeleton (or ~5 table-shaped skeleton rows inside the glass shell). No spinner-only blank. | (skeleton) |
| Slow (>8s) | `AsyncState` slow escalation is available; low value for a plain DB read — default copy acceptable, not required. | default |
| Error | `AsyncState` error: `AlertTriangle` (`text-red-300`) + heading + body + **"Tentar novamente"** (→ `refetch`). | heading **"Não foi possível carregar os usuários."** / body **"Verifique a conexão e tente novamente."** |
| Empty | **Defensive only** — the logged-in admin is always in the roster, so a truly empty list is effectively unreachable. If rows = 0, show the centered empty block, never a blank surface. | heading **"Nenhum usuário encontrado."** / body **"Crie o primeiro usuário com o botão 'Novo usuário'."** |
| Success | `GlassCard` + `<Table>` with all rows. | (data) |

**Mutation-pending (create / mudar_papel / ativar-desativar / resetar):** the acting button/AlertDialogAction shows an inline `Loader2` + verb-in-progress label ("Criando…"/"Salvando…"/"Desativando…"/"Enviando…") and is `disabled` (no double-submit). Other rows stay interactive.

**Optimistic vs refetch:** default = **on-success `invalidateQueries(usuariosRhKeys.list)` (simple refetch)** — the roster is small and the anti-lockout count must reflect server truth; optimistic update is allowed at discretion but must reconcile on settle. TanStack Query `staleTime` 5min / retry 2 (project default) applies to the list query.

## Accessibility (WCAG-AA gate — axe-core Tier-A must stay green)

- **Contrast:** only the AA-verified tint/text pairs above (Phase 16). Turquoise is fill/border/focus, never small-text color.
- **Touch/click targets:** CTA, dropdown trigger, dialog + alert-dialog actions, retry ≥ `min-h-[44px]` (and `min-w-[44px]` for the icon-only Ações trigger).
- **Names:** icon-only controls carry `aria-label` (`"Ações"`, `"Novo usuário"` if icon-only). Table is a real `<table>` with `<TableHead>` headers; `Dialog`/`AlertDialog` get titles + descriptions (Radix wires `aria-labelledby`/`aria-describedby`).
- **Keyboard:** all actions reachable — Radix DropdownMenu roving focus, Dialog/AlertDialog focus-trap + Esc, tooltips triggered by real focusable `<button>` (disabled-action tooltips use the `inline-flex` wrapper idiom so they remain focus-reachable).
- **Feedback to AT:** sonner toasts announce via its live region; keep messages text-only (no PII beyond the target email/name already on screen).
- **No color-only meaning:** every status/role is labeled text, not just a hue.
- **Focus-visible:** preserve the shadcn/Radix `focus-visible` ring (turquoise/`--ring`); never remove outlines.
