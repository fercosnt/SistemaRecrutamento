**Severidade:** P1 — bloqueia o fluxo end-to-end do candidato.
**Origem:** introduzido pelo Plan 04-07 (rewrite full single-page RHF).

ausente. Não dispara erro no console nem no build.

**Classes inválidas encontradas:**

|---|---|
| `bg-primary-700` | `bg-primary` |
| `hover:bg-primary-800` | `hover:bg-primary/90` |
| `text-primary-700` | `text-primary` |
| `text-primary-800` | `text-primary` |
| `bg-primary-100` | `bg-primary/10` |
| `focus:border-primary-700` | `focus:border-primary` |

**Linhas em FormularioCandidaturaPage.tsx:** 405, 418, 462, 490, 536, 601, 616, 632, 664, 699.

**Evidência (Elements panel inspeção):**

### F-04-08-D — Token bg-primary quebrado em todo o projeto (design system debt)

`LoginCandidatoPage.tsx:393`. O Plan 04-07 não seguiu o precedente.

`text-primary` / `focus:border-primary` por `bg-[#00109E]` / `text-[#00109E]` /
`focus:border-[#00109E]` em FormularioCandidaturaPage.tsx (10 ocorrências).

**Phase 5 follow-up:** reparar a definição do token `--primary` (3 opções
documentadas em CARRYOVER-B `<followups>` — recomendada: definir `--primary` em
HSL components separadamente do HEX `--brand-primary`). Após Phase 5 corrigir o

### F-04-08-F — Deferred-upload incompatível com Zod required (BLOCKER)

Após Carryover-B (commit pós beaec2d) o visual ficou correto, mas UAT-J01 ainda
travou: clicar "Enviar candidatura" não dispara onSubmit, sem mensagem visível,
sem requests no Network. Diagnóstico via DOM inspection:

- `button[type="submit"]` está `disabled={false}` (não bloqueado pelo gate `submitDisabled`).
- Click chega no DOM (hover styling funciona).
- `form.dispatchEvent(submit)` retorna `false` → `preventDefault()` foi chamado (RHF padrão — não é smoking gun por si só).
- Inspeção dos inputs confirma: `respostas.<UUID>` para texto/radio/numérico TODOS preenchidos. RHF interno tem dado válido para os 3.
- Inspeção `[class*="text-red"]` retorna 4 elementos: 3 são asteriscos `*` ao lado de labels obrigatórios + 1 com texto vazio (slot de erro renderizado mas mensagem em branco).
- ⇒ **Validação está falhando com mensagem vazia.**

**Causa raiz:** conflito entre 3 plans ao redor do CV:

1. **Plan 04-03** (`cvUploadService`): pattern just-in-time upload — `validateCV` no select, `uploadCV` só durante submit.
2. **Plan 04-04** (`buildCandidaturaSchema` em `src/features/vagas/schemas/candidaturaFormSchema.ts:132-146`): exige `curriculo: z.object({ path: z.string().min(1, 'Currículo obrigatório'), name, size })` — campo REQUIRED, sem `.optional()`.
3. **Plan 04-07** (FormularioCandidaturaPage):
   - `handleFileSelect` (linha 172-198): seta apenas `cvFile` local. Comentário inline: *"cvPath is set on actual upload (just-in-time during onSubmit) — D-09 says no auto-upload-on-select."*
   - `useEffect` (linha 162-170): popula `form.curriculo` SOMENTE quando `cvFile && cvPath`.
   - `cvPath` só é setado dentro de `onSubmit` após `uploadCV()` resolver (linha 240+).

**Sequência do bug:**
```
Usuário seleciona PDF
  → cvFile setado, cvPath = null
  → form.curriculo permanece undefined (default da linha 136)
Usuário preenche 3 perguntas
  → form.respostas.<id> preenchidos
Usuário clica "Enviar candidatura"
  → form.handleSubmit(onSubmit) invocado
  → Zod valida → curriculo é undefined mas schema exige .min(1) em path
```
