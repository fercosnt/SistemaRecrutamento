AuthError (D-17 — from RESEARCH.md lines 273-291, 03-PATTERNS.md lines 50-82):
```typescript
export class AuthError extends Error {
  constructor(
    public override readonly message: string,
    public readonly code:
      | 'INVALID_CREDENTIALS'
      | 'EMAIL_NOT_CONFIRMED'
      | 'RATE_LIMITED'
      | 'NETWORK_ERROR'
      | 'SERVER_ERROR'
      | 'UNKNOWN_ERROR',
    public readonly field?: 'email' | 'senha',
    public readonly retryAfterSeconds?: number,
    public readonly originalError?: unknown
  ) {
    super(message)
    this.name = 'AuthError'
  }
}

export function isAuthError(err: unknown): err is AuthError {
  return err instanceof Error && err.name === 'AuthError'
}
```

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-07 | DoS | `mapSupabaseError` receives malformed/non-Error input and crashes | mitigate | Type guard `if (!(err instanceof Error))` short-circuits to `UNKNOWN_ERROR` before property access |
| T-03-08 | Tampering | Client bypasses Zod via DevTools to submit weak password | accept | Server-side Supabase Auth rejects weak passwords (error.code='weak_password' → SERVER_ERROR branch). Zod is UX, not security. |

| T-03-02 | Info Disclosure | Different AuthError messages for "email not found" vs "wrong password" leaks enumeration | mitigate | Both map to single `INVALID_CREDENTIALS` message (D-01). No split. |
| T-03-pw-regex | DoS | Pathological password input triggers ReDoS in `.refine` regex | accept | Regexes are trivial character-class checks `/[A-Z]/` / `/[a-z]/` / `/[0-9]/` — no backtracking; safe. max(100) caps string length. |
