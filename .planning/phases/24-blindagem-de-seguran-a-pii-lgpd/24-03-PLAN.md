<objective>
Close the essay-verdict leak with the mechanism the researcher flagged as the single most important thing not to get wrong. Because RH and the candidate are the SAME Postgres role (`authenticated`), a column REVOKE that hides the verdict from the candidate would ALSO hide it from RH. The correct fix is: candidate-DENY the base-table row-SELECT policy and route the candidate's own-row read through a SECURITY DEFINER RPC that projects only safe columns. This plan is isolated on purpose so the executor never blurs it with the column-REVOKE-safe SEC-01/07 (24-02).

Purpose: A candidate doing `GET /rest/v1/redacoes_candidato?select=red_flag_etico` (or any verdict column) on their own row must get nothing; RH must still read the full verdict; the candidate still sees their own redação text/status via the RPC.
Output: 1 migration file, 1 client rewire, 1 SQL smoke, 1 vitest guard.
</objective>
