# Phase 20 — UI Design Contract

> Visual and interaction contract for the interview-guide EDIT mode (ENTREV-06/07). Turns the read-only
> `GuiaEntrevistaPanel` into an editable one (RH-facing, desktop, glass UI Beauty Smile). Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.

**Scope lock:** edit-mode toggle · editable question row (inline `pergunta` text + `dimensão`) ·
add-manual-question control · delete control · up/down reorder buttons · `IA`/`Manual` origem badge ·
Save/Cancel ("Salvar edições") affordance · dirty/saving/error states for the batch-save (reuse
`<AsyncState>` error idiom for the in-flight save). **IA-only fields (BARS anchors / probes / flags) stay
read-only display.** No new screens. The panel still lives in the `EntrevistaWorkspace` "Guia de entrevista"
tab under a `<Glass variant="white">` shell — this contract governs only what renders *inside* that shell.

**Pre-populated from:** CONTEXT.md (Área 3 binding; Área 1/2 inform origem badge + merge invariant) ·
codebase scout (existing primitives, glass tokens, AsyncState, SugestaoIABadge, alert-dialog pattern).
No user questions were required — Área 3 already locked the interaction model.

## Spacing Scale

Declared values (multiples of 4). Mirrors the existing read-only `PerguntaRow` (`px-3 py-3 space-y-1`)
so edit mode is visually continuous with view mode.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gap inside badges/buttons (`gap-1`); reorder-button stack gap |
| sm | 8px | Gap between controls in a row (`gap-2`); list item internal `space-y` (`space-y-2`) |
| md | 12px | Row inner padding (`px-3 py-3`) — matches existing PerguntaRow; gap between question rows (`space-y-3`) |
| lg | 16px | Panel section vertical rhythm (`space-y-4`) — matches existing panel |
| xl | 24px | Glass shell padding (`p-6`) — host-owned, unchanged |

Exceptions:
- **44px minimum touch/click target** for every interactive control (toggle, Salvar, Cancelar, add,
  delete, up, down) — `min-h-[44px]` (icon-only reorder buttons may be `h-9 w-9`/36px *only if* keyboard-
  focusable with a visible ring; prefer 44px). Inherits the existing panel convention (`min-h-[44px]` on
  the generate CTAs).
- `12px` (md) is an intentional carry-over from the live `PerguntaRow` — it is on the 4-grid; do not "round
  up" to 16 and break visual continuity with view mode.

## Typography

Carried verbatim from the existing `GuiaEntrevistaPanel` so edit mode does not introduce a second type
scale. Exactly 3 sizes + 2 weights in active use.

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Panel heading | 20px (`text-xl`) | 600 (`font-semibold`) | 1.2 (heading) | "Guia STAR/PEI" header (unchanged) |
| Body / question text | 16px (`text-base`) | 400 body, 600 for the leading number | 1.625 (`leading-relaxed`) | Question text (view) + `Input` value (edit) |
| Label / meta | 14px (`text-sm`) | 600 (`font-semibold`) | 1.5 | Field labels, hints, secondary copy |
| Micro / badge | 12px (`text-xs`) | 600 (`font-semibold`) | 1.4 | `IA`/`Manual` badge, dimensão pill, "Âncoras BARS 1–5" eyebrow |

Rules:
- The inline `Input` for `pergunta` MUST match the displayed question typography (`text-base text-white/90`)
  so toggling edit mode does not reflow the row height noticeably.
- No new weight beyond 400/600. No size outside {12, 14, 16, 20}.

## Color

Glass UI Beauty Smile on a brand-gradient backdrop. Surfaces are translucent white-on-dark; this phase
adds **no new fills** — accent stays reserved.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | app brand gradient + `bg-white/[0.03]–white/15` glass surfaces (`Glass variant="white"`) | Panel shell, row backgrounds, neutral controls |
| Secondary (30%) | `border-white/10–white/25` + `bg-white/5–white/20` | Row borders, neutral buttons (toggle, Cancelar, reorder), inputs, dimensão pill |
| Accent (10%) | `#35BFAD` (brand teal) | RESERVED — see list below |
| Destructive | `text-red-300` / `border-red-400/30` / `bg-red-500/15` | Delete-question affordance + its confirm dialog ONLY (matches TranscricaoReviewPanel red idiom) |

**Accent (`#35BFAD`) reserved for — explicit, closed list:**
1. The `Sparkles` icon in the `SugestaoIABadge` header (existing).
2. The `Sparkles` icon on the two generate CTAs (existing).
3. The `IA` origem badge tint (`border-[#35BFAD]/40 bg-[#35BFAD]/10` + Sparkles) — mirrors SugestaoIABadge,
   signalling "this question came from the AI".
4. The primary **"Salvar edições"** button (the single primary action in edit mode) — `GlassButton`
   tinted accent so the save reads as the committing action.

**Accent is NOT used for:** the `Manual` badge (neutral white pill — human-authored, no AI tint), the
edit-mode toggle, Cancelar, reorder up/down, add-question, delete, inputs, or selects. Accent never
carries a score and never appears on a destructive control (RNF-07a + existing badge discipline).

- **`IA` badge:** `#35BFAD` tint + `Sparkles` (h-3 w-3). Text "IA".
- **`Manual` badge:** neutral `border-white/15 bg-white/5 text-white/70` (same family as the dimensão
  pill) + no icon (or `Pencil` h-3 w-3). Text "Manual". Human origin = neutral, not accent.

**Destructive actions:**

| Action | Confirmation approach |
|--------|----------------------|

## Interaction Contract (edit mode)

State machine for the panel (single source of truth = `EntrevistaWorkspace` host or a local edit reducer):

| State | Trigger | Render |
|-------|---------|--------|
| **view** (default) | guide loaded | Read-only rows (current `PerguntaRow`) + each row shows `IA`/`Manual` badge + "Editar guia" toggle visible. IA-only fields read-only. |
| **edit** | "Editar guia" clicked | Each row → `EditablePerguntaRow`: inline `Input` (pergunta) + `Select` (dimensão) + `Trash2` + up/down. "Adicionar pergunta" control at list end. Footer: "Salvar edições" (accent) + "Cancelar". BARS/probes/flags still read-only display. |
| **dirty** | any field/order/add/delete change in edit | "Salvar edições" enabled; optional dirty hint shown. |
| **saving** | "Salvar edições" clicked | Salvar → "Salvando…" + disabled; whole panel non-interactive (or controls disabled). Batch-save entire edited guide via RPC. |
| **save-error** | RPC rejects | Toast + AsyncState error region (or inline error band) with retry; edit state PRESERVED (user does not lose edits). `insufficient_privilege` → permission copy. |
| **save-success** | RPC resolves | Toast "Edições do guia salvas."; exit to **view** with the saved guide; new manual rows now carry `Manual` badge. |

Locked interaction rules:
- **Inline edit, not modal**, for existing rows (CONTEXT Área 3 + Claude's discretion → inline chosen for
  continuity; row swaps display text for an `Input`/`Select` in place).
- **Add-question = inline form** appended at list end (not a separate screen/modal): `Input` (Pergunta) +
  `Select` (Dimensão) + "Adicionar"/"Cancelar". New question marked `origem:'manual'`.
- **Reorder = up/down buttons** (CONTEXT Área 3 — no DnD). Keyboard-accessible; boundary buttons disabled.
- **Batch save**: one RPC call commits the whole edited guide (CONTEXT Área 2). No per-row autosave.
- IA-only fields (`ancoras_bars`/probes/flags) render but are **never** editable in this phase (deferred).
- Empty guide: "Editar guia" disabled; empty-state copy unchanged. (You cannot edit a guide that doesn't
  exist — generate first.)

## Accessibility

- Every interactive control ≥44px target (or 36px with a visible focus ring for icon-only reorder).
- Icon-only buttons (delete, up, down) carry `aria-label` (copy above). `aria-hidden` on decorative icons.
- `Select` and `Input` wired to a `Label` (`htmlFor`) in the add-question form.
- Edit/view toggle communicates state (the row swaps to form fields — focus moves to the first field on
  enter-edit is a nice-to-have, not required).
- Save error uses the AsyncState error contract: static PT-BR copy keyed by code, never the raw error.
- Reorder boundary buttons use `disabled` (not removal) so focus order is stable.
