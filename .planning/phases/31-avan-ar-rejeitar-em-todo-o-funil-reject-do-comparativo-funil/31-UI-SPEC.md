# Phase 31 — UI Design Contract

> Visual and interaction contract for **Avançar/Rejeitar em Todo o Funil + Reject-do-Comparativo (funil-02)**. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope reality:** this is a REUSE-heavy phase. One genuinely new component (`RejeitarCandidaturaDialog`) wired into three EXISTING RH surfaces, plus an advance/regress affordance. It does NOT restyle the funnel, Kanban, hub, or comparativo — it adds action affordances that match sibling components already on those surfaces. No agendamento, CV, KPIs, or fila (Phases 32–35).

**Two rendering surfaces to keep straight:**

- **Light modal surface** (`AlertDialogContent` = `bg-background` `#FFFFFF`, `text-foreground` neutral-900) — the new `RejeitarCandidaturaDialog` body renders here and uses **default light shadcn tokens** (`foreground` / `muted-foreground` / `input` / `destructive`), NOT the dark-glass white-alpha styling.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`gap-1`, `p-1`) | Icon gaps, badge inner padding |
| sm | 8px (`gap-2`, `p-2`) | Compact spacing — card action stack, select↔textarea |
| md | 16px (`gap-4`, `p-4`) | Default element spacing, dialog field gaps |

| xl | 32px (`gap-8`) | Layout gaps (inherited on host surfaces) |
| 2xl | 48px | Major section breaks (inherited) |

These are min-heights, not spacing tokens. `AlertDialogContent` fixed padding `p-6` (24px, shadcn default).

## Typography

Scale sourced from globals.css `--text-*` / `--font-weight-*`. This phase touches **3 sizes + 2 weights** (dialog is small-surface, no display type).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Dialog title (`AlertDialogTitle`) | 18px (`text-lg`) | 600 semibold | 1.2 |
| Body / description / options | 16px (`text-base`) → 14px (`text-sm` in dense action rows) | 400 normal | 1.5 |
| Label / counter / button text | 14px (`text-sm`) | 600 semibold | 1.5 |

- **Weights:** exactly two in play — **400 (normal)** for descriptions/placeholder/option copy, **600 (semibold)** for labels, counter, and all button/action text. (The codebase also defines 500/700/800; this phase does not introduce them.)
- **Body line-height 1.5** (`leading-[1.5]`, matches `ComparativoScreen` justificativa cells). **Heading line-height 1.2** for the dialog title.

## Color

60/30/10 mapped to the RH glass shell (the surface the triggers live on). The **modal dialog itself** is a light shadcn surface (see Design System note) and uses foreground/muted tokens.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#00109E` — `--primary` / `bg-primary` | RH app-shell background, glass base gradient |
| Secondary (30%) | white-alpha glass (`bg-white/5`–`bg-white/20`, `border-white/10–20`) | Cards, Kanban columns, hub panels, comparativo table chrome |
| Accent (10%) | `#35BFAD` — `--accent` / turquoise | see reserved-for list below |
| Destructive | `#EF4444` — `--destructive` (red-500 family: `red-500/10` glass fill, `text-red-300` on dark, `bg-destructive` on light) | Reject action only |

**Accent `#35BFAD` reserved for (explicit list — never "all interactive elements"):**
- The **Avançar** confirm button on dark-glass surfaces (`bg-[#35BFAD] text-[#00109E]`, matching the existing `ComparativoScreen` Avançar).
- The current-etapa chip and the single dominant "Abrir/Revisar {etapa}" CTA already present in `HubCandidatoRH` (unchanged — not re-styled here).
- NOT used for Rejeitar, Retroceder, Cancelar, or the reject-dialog confirm.

**Destructive `#EF4444` reserved for (reject only):**
- Rejeitar **trigger** buttons on dark glass: `border-red-500/40 bg-red-500/10 text-red-300 hover:bg-red-500/20` (verbatim from `ComparativoScreen`).
- The reject-dialog **confirm** action on the light modal: `bg-destructive text-destructive-foreground hover:bg-destructive/90`.
- The counter **error text** when justificativa < 50 (`text-destructive` on light / `text-red-300` on dark).

**Retroceder (regression)** is a **neutral** action, not destructive and not accent — it is a lateral move, not a rejection. On dark glass: `border-white/20 bg-white/5 text-white/80 hover:bg-white/10` (matches the hub "Revisar {etapa}" chips). Reserving red for reject keeps the audit-consequence signal honest.

## Interaction States (RejeitarCandidaturaDialog)

The counter is UX; the **server (RPC `rejeitar_candidatura` ≥50 RAISE) is the authority**. The client mirror only prevents an obviously-doomed submit.

| State | Visual contract |
|-------|-----------------|
| Idle / open | Motivo `<Select>` placeholder "Selecione o motivo"; empty `<Textarea>`; counter `0 / 50 mín.` in `text-muted-foreground`; confirm **disabled**. |
| Motivo chosen, justificativa < 50 | Counter still `text-muted-foreground` (`N / 50 mín.`); helper line `A justificativa precisa de pelo menos 50 caracteres.` in `text-destructive`; confirm **disabled**. |
| Valid (motivo set + trimmed ≥ 50) | Counter flips to `text-foreground`; helper hidden; confirm **enabled** (`bg-destructive`). |
| Submitting (mutation pending) | Confirm shows `<Loader2 className="animate-spin" />` + "Rejeitando…"; confirm + cancel **disabled** (no double-submit). |
| Success | Dialog closes; `toast.success` (see copy); TanStack invalidates `candidaturasKeys.all` + `vagasKeys.all` + `triagemKeys.all`. |
| Error (RPC RAISE / `TriagemServiceError`) | Dialog stays open; `toast.error` (see copy); fields preserved so the RH can fix + resubmit. |

**Whitespace rule:** the counter and the enable-gate both count `btrim()`-trimmed length (mirror the server's `btrim` before `char_length >= 50`) so leading/trailing spaces can't fake a pass.

**Retroceder dialog:** destino `<Select>` lists only stages with a **lower** enum ordinal than `etapa_atual` and non-terminal (never `aprovado`/`rejeitado`, never a forward stage). Justificativa `<Textarea>` required non-empty (no 50-floor); confirm disabled until destino set + justificativa trimmed non-empty. The trigger's `RAISE 'Regressão de etapa exige justificativa preenchida'` is the authority.

**Destructive actions in this phase + confirmation approach:**
1. **Rejeitar** (Kanban · hub · comparativo) → `RejeitarCandidaturaDialog` modal: motivo + justificativa ≥50 (server-enforced) before an enabled destructive confirm. Reversible (RH can re-advance manually) — copy says so; do not imply permanence.
2. **Retroceder** → confirm dialog with destino + required justificativa. Non-destructive but consequential (audited trail row); neutral styling, explicit confirm.
3. **Avançar** → lightweight confirm (`AlertDialog`), no free-text. Not destructive.

**Language invariants (project CLAUDE.md / RNF):** never "teste psicológico" → use "avaliação comportamental/cognitiva". Never imply the system auto-rejects by score (RNF-07a) — every reject is a human write with a justificativa. No score/número aparece na cópia de rejeição.

## Accessibility Notes (contract, not exhaustive)

- Motivo `<Select>` and justificativa `<Textarea>` each have an associated `<label htmlFor>` (or `aria-label`); the counter is `aria-live="polite"` so it announces on threshold cross.
- The too-short helper is tied to the textarea via `aria-describedby`; when the confirm is disabled, the reason is visible text (not color-only).
- Card `DropdownMenu` trigger is a real `<button>` with `aria-label="Ações do candidato"` and Radix roving focus (keyboard-operable — advance/regress/reject reachable without drag-drop).
- Destructive vs accent vs neutral is never conveyed by color alone — each carries an icon (`X` reject, `ArrowRight` advance, `ArrowLeft`/`Undo2` regress) + a text label.
- Contrast: dark-glass triggers keep the established `text-red-300`/`text-white/80` (already ≥4.5:1 over composited glass, per Phase-15 FX-07 precedent); light-modal confirm uses `destructive-foreground` on `destructive` (token-guaranteed).
