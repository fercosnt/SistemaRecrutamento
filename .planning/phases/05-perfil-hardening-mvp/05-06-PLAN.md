<objective>
Wave 5 (carve-out) — migrate password recovery from PKCE magic-link to email-OTP (D-15/D-16). This is the heaviest single Phase 5 item and is isolated into its own plan for bisect-friendly rollback. Switch recovery to "type the 6-digit code from the email": `resetPasswordForEmail` (unchanged) → user types the OTP → `verifyOtp({type:'recovery'})` establishes a session → `updateUser({password})`. This eliminates the cross-browser `code_verifier` dependency that made the PKCE deeplink fail silently. Requires a Supabase Dashboard email-template edit ({{ .Token }}) — a human checkpoint — plus real-email UAT. Also wraps the perfil change-password widget in a proper <form> (a11y, HARD-04 overlap).

Purpose: Hardens the existing AUTH-03/04 recovery flow by removing the documented cross-browser limitation (Phase 3 03-07 finding). OTP-entry also mitigates email-prefetch token consumption.

Output: OTP-based recovery (service + schema + hook + 2 pages + rewritten E2E) + Dashboard template config + UAT.
</objective>
