# Phase 11 — UI Design Contract

> Visual and interaction contract for the **Avaliação Assíncrona (Etapa 3)** candidate flow + the RH scorecard read view. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope of this contract:** the avaliação container (`/candidato/avaliacao/:candidatura_id`), the SJT multiple-choice screen, the SJT open-case screen, the autosave/"salvo automaticamente" affordance, the back-lock / wrong-etapa locked states, loading/submitting/error states, and a brief RH scorecard note. **Mobile-first** (this is the candidate side). The candidate **never** sees scores, thresholds, or pass/fail — only neutral progress (RNF-07a).

## Spacing Scale

Declared values (multiples of 4; matches existing glass shell which uses `space-y-4/6/8`, `gap-4`, `p-6`, `py-20`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside badges/status pills (`gap-1`) |
| sm | 8px | Compact element spacing, radio option inner padding (`gap-2`) |
| md | 16px | Default gap between test cards and between form blocks (`space-y-4`, `gap-4`) |
| lg | 24px | Card inner padding (`p-6`), gap between major sections (`space-y-6`) |
| xl | 32px | Container vertical rhythm between panels (`space-y-8`) |
| 2xl | 48px | Header-to-content break, empty/all-done state vertical padding (`p-12`) |
| 3xl | 64px | Page top/bottom breathing room (`py-20` from shell) |

**Exceptions:** Touch targets (radio rows, primary CTA, navigation buttons) must be ≥44px tall for mobile tap accuracy — pad radio option rows to a minimum `min-h-[44px]` even though 44 is not on the 4-scale (mobile a11y exception, candidate persona).

## Typography

Family: Helvetica Neue (`--font-family`). Exactly 4 sizes, 2 weights. Body line-height 1.5, heading line-height 1.2. On the candidate glass surface, text is white with `drop-shadow-md` for legibility over the gradient (shell convention).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / option text / scenario | 16px (`text-base`) | regular (400) | 1.5 |
| Label / status pill / helper / autosave note | 14px (`text-sm`) | semibold (600) | 1.4 |
| Card title / question heading | 20px (`text-xl`) | semibold (600) | 1.2 |
| Page heading (container H1) | 28px (`text-3xl` ≈ 30px → cap at 28 for mobile) | semibold (600) | 1.2 |

**Notes:**
- The legacy shell uses `text-5xl` H1 — for this **mobile-first** phase, downscale the container heading to `text-3xl` (responsive `md:text-4xl` max) so it fits a phone viewport without wrapping awkwardly.
- Scenario / case prompt body must be 16px at 1.5 line-height for readability — never smaller, even when the scenario is long.
- Only two weights: 400 (body, scenario, option text) and 600 (titles, labels, CTAs, status). No 500/700/800 in this phase's surfaces despite their availability in `--font-weight-*`.

## Color

The candidate side is the **glass-over-gradient** persona surface: the dominant and secondary roles are expressed as translucent white over the brand gradient, not flat brand fills (this is the established candidate shell language).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#00109E` brand-primary gradient (via `BackgroundImage background="gradient"`, `bg-[#00109E]` solid base under it) | Full-page background behind all glass |
| Secondary (30%) | `bg-white/5`–`bg-white/20` translucent white (GlassCard/GlassPanel) | Test cards, form panels, navbar, status pills |
| Accent (10%) | `#35BFAD` brand-accent | See reserved list below |
| Destructive | `#EF4444` (`--destructive`) | Locked / blocked / error iconography ONLY — never a button fill in the candidate flow (there are no destructive candidate actions here) |

**Accent (`#35BFAD`) reserved for — explicit list:**
1. The **"salvo automaticamente"** autosave affordance (check icon + text tint) — signals "your work is safe", the single accent touchpoint on the candidate side.
2. The **`SugestaoIABadge`** accent tint (`border-[#35BFAD]/40 bg-[#35BFAD]/10`, Sparkles icon) — **RH scorecard view only**, never candidate-facing.
3. The **completed-test** check mark / 100% progress fill on a test card in the container.

Accent is NOT used for: the primary CTA, radio selection state, links, or generic interactive hover. Those use the glass-white language (`bg-white/20` → `bg-white/30` selected, white text). This keeps accent rare and meaningful.

**Status / progress colors (neutral, RNF-07a-safe — candidate side):** test status uses neutral tints only, never red/green pass-fail semantics:
- `pendente` → `text-white/70` + `bg-white/10` pill, label **"Pendente"**, `Circle` icon.
- `feito` → `#35BFAD` accent check + 100% progress, label **"Concluído"**, `CheckCircle2` icon.
- `bloqueado` (back-lock / wrong etapa) → `text-white/60` muted + `Lock` icon, label **"Indisponível"**. The candidate never sees a red "failed" state — scoring outcomes are invisible to them.

## Copywriting Contract

All copy pt-BR. Product language rule (LGPD-04): use **"avaliação comportamental/cognitiva"**, NEVER "teste psicológico". Candidate copy is neutral and reassuring; it never references scores, thresholds, percentages, pass/fail, or "aprovado/reprovado" for the assessment.

|---------|------|

### Autosave affordance ("salvo automaticamente")

| State | Copy | Visual |
|-------|------|--------|
| Saving (in-flight) | Salvando… | spinner (`Loader2` animate-spin), `text-white/70` |
| Saved | **Salvo automaticamente** | `Check` icon in `#35BFAD`, `text-white/80`, fades in |
| Save failed (transient) | Não foi possível salvar agora — tentando novamente… | `AlertCircle` muted-amber, no candidate action required |

Placement: inline, top-right of the test screen, persistent. Updates on each 30s debounced upsert and on blur of the textarea.

### States

| Element | Copy |
|---------|------|
| Loading (container / screen) | Skeleton glass cards (`animate-pulse`), no text |
| Error state (load failed) | **Não foi possível carregar a avaliação.** Verifique sua conexão e tente novamente. + **Tentar novamente** button |
| Submitting (in-flight) | CTA → "Enviando…" disabled + spinner; screen inputs disabled |
| Submit success | toast.success **"Avaliação enviada com sucesso"** + return to container with that card now **Concluído** |

### Back-lock / wrong-etapa (blocked, neutral — never alarming)

| Element | Copy |
|---------|------|
| Already submitted (read-only) | **Esta avaliação já foi enviada.** Suas respostas foram registradas. *(content shown read-only / disabled, `Lock` icon)* |
| Wrong etapa / not invited | **Esta avaliação não está disponível.** Ela aparecerá aqui quando for a sua etapa. + **Voltar ao painel** button → `/candidato/dashboard` |
| Etapa advanced mid-session | **Sua etapa avançou.** Esta avaliação foi encerrada e suas respostas já estão salvas. + **Voltar ao painel** |

### "Destructive" / irreversible confirmation

There are **no destructive (delete) actions** in this phase. The only irreversible candidate action is **submitting** a test (back-lock makes it read-only afterward). Gate it with an `alert-dialog` confirm — NOT because it deletes data, but because it cannot be edited after:

| Action | Confirmation |
|--------|--------------|
| Enviar resposta / Concluir avaliação | Title: **Enviar avaliação?** — Body: **Após enviar, você não poderá editar suas respostas.** — Confirm: **Enviar** — Cancel: **Revisar** |

## RH Scorecard View (brief note — read-only, role-gated, NOT candidate-facing)

A separate RH-facing surface reads `scores_candidato` via the **allowlist role-gated** projection (reuse the Phase-10 panel pattern — NEVER `select('*')`; see `reference_select_star_leaks_pii`). This is the **desktop RH shell** (not the glass candidate shell). Contract for this view:

- **Structured scorecard per dimension:** one row/card per SJT dimension (multiple-choice breakdown by item; open-case BARS dimensions 1-5 → composite 0-25). Show the score, the per-item/per-dimension breakdown from `metadata` jsonb, and AI citations + red_flags for the open case.
- **RNF-07a guardrail mandatory:** every AI-derived score block carries the **`SugestaoIABadge`** (`SUGESTAO_IA_COPY = "Sugestão da IA — decisão é sempre humana"`, accent `#35BFAD`, `Sparkles` icon). The badge is informational only — it never colors a score and never sits on an action. Reuse the existing component `src/features/triagem/components/SugestaoIABadge.tsx` (variant `full` on panel headers, `compact` inline).
- **`pendente_humano` surfacing:** when threshold logic flags `<60%`/`≥1 atencao` (multiple choice) or `<13/25`/`≥1 red_flag` (open case), the RH scorecard shows a neutral **"Requer revisão humana"** marker — the system **never auto-rejects** and never changes etapa by score.
- **Score color rule:** scores use neutral/structured presentation, not red/green pass-fail tints, so the accent badge stays the single AI signal. The candidate side reads zero score data (RLS + allowlist deny).

This phase's UI-SPEC defines the candidate flow in full detail; the RH scorecard layout inherits the Phase-10 panel contract and is specified at plan time against that precedent.
