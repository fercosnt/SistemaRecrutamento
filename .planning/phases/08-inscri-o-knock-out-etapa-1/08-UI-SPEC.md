# Phase 8 — UI Design Contract

> Visual and interaction contract for the candidate-facing inscrição + knockout (Etapa 1) flow. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Persona:** Candidato (público, **mobile-first**). **Locked to the existing Beauty Smile design system** — do NOT invent a new visual language. All tokens below are read from the live `src/styles/globals.css` + `tailwind.config.js`; this phase consumes them, it does not redefine them.
>
> **Reuse-over-invention mandate (this phase is a thin M2 layer on M1/Phases 6-7):**
> - Qualification + knockout questions render through the **existing dynamic renderer** — `src/features/vagas/hooks/useVagaPerguntas.ts` + `buildCandidaturaSchema` (`src/features/vagas/schemas/candidaturaFormSchema.ts`) + `src/lib/opcoes/opcoesNormalize.ts` — inside the existing **`FormularioCandidaturaPage.tsx`**. No new question renderer.
> - LGPD-clean profile collection rides the existing **`/cadastro` multi-step** (RHF+Zod per step); the only change is REMOVING fields (CPF, gênero), never adding a new collection surface.
> - The knockout option is visually indistinguishable from any other qualification option (D-06 [LOCKED]) — there is **no separate "knockout block"**.
> - Rejection + survivor feedback wires into the existing **`DashboardCandidatoPage.tsx` / `MeuPerfilCandidatoPage.tsx`** status surfaces (which already use the glass `Badge` + status-color helpers).

## Spacing Scale

The project ships an 8-point-aligned scale in `src/styles/globals.css` (`--spacing-*`). This phase uses **only** the multiples-of-4 subset below. Do NOT introduce new spacing values.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon-to-label gap inside buttons/badges, inline error → field gap |
| sm | 8px | Compact spacing between a label and its input; radio/checkbox option internal padding |
| md | 16px | Default vertical rhythm between form fields; card inner padding on mobile |
| lg | 24px | Padding inside the glass card (`GlassCard` ships `p-6`); gap between question groups |
| xl | 32px | Vertical gap between the major form sections (resumo da vaga → currículo → qualificação → submit); `GlassPanel` ships `p-8` |
| 2xl | 48px | Top/bottom breathing room above the result/feedback state on mobile |
| 3xl | 64px | Page-level top spacing under the fixed `CandidatoNavbar` on desktop |

**Exceptions:** Interactive touch targets (radio options, single_choice cards, primary CTA) must be **≥44px tall** for mobile-first tap accuracy (WCAG 2.5.5 / Beauty Smile mobile persona). 44px is a touch-target floor, not a spacing token — it is achieved via min-height + py-3 (12px) padding, not by inventing a 44px gap.

## Typography

Declared from `--text-*` / `--font-weight-*` in `src/styles/globals.css`. Exactly 4 sizes, exactly 2 weights for this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`--text-base`, `text-base`) | 400 (`--font-weight-normal`) | 1.5 |
| Label | 14px (`--text-sm`, `text-sm`) | 600 (`--font-weight-semibold`) | 1.5 |
| Heading (question group / section) | 20px (`--text-xl`, `text-xl`) | 600 (`--font-weight-semibold`) | 1.2 |
| Display (page title / result heading) | 28px (`--text-3xl`, `text-3xl`) | 600 (`--font-weight-semibold`) | 1.2 |

Rules:
- Body copy (question text, neutral rejection message, success confirmation) is **16px / 400 / 1.5** — never below 16px for candidate-facing reading text (mobile legibility).
- Inline validation errors use Label size (14px) in the destructive color.
- Only two weights ship: **400** (body/reading) and **600** (labels, headings, CTA). Do NOT use 500/700/800 in this phase even though the tokens exist.

## Color

Beauty Smile palette (semantic tokens are HSL channel triplets per the globals.css D-07/D-26 note; raw brand hex also available). **Dominant is the deep blue brand; turquoise is the reserved accent.**

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` / `--background` (with `BackgroundImage` behind glass) | Page background and the glass card surfaces the form lives on |
| Secondary (30%) | brand-primary deep blue `#00109E` (`--primary`) + neutral surfaces (`--muted` #F1F2F2, `--card`) | Section headings, primary text emphasis, glass-primary panels, neutral field chrome |
| Accent (10%) | brand-accent turquoise `#35BFAD` (`--accent`) | **Reserved — see list below** |
| Destructive | `#EF4444` (`--destructive`) | Inline form validation errors only |

**Accent (turquoise `#35BFAD`) reserved for — explicit list:**
1. The **primary submit CTA** ("Enviar candidatura") — the single dominant action on the form.
2. The **active/selected state** of a single_choice / radio qualification option (selected ring + check).
3. The **success/survivor confirmation** icon + heading accent (candidate who passed knockout, candidatura → triagem).
4. **Focus rings** on interactive inputs (existing `--ring` is brand-primary; where a glass surface needs contrast, the accent ring is permitted on the active step element).

Accent is NOT used for: body text, ordinary borders, every button, the status badges, or the rejection state.

**Semantic state colors (existing tokens — used for status display, NOT counted in the 60/30/10 split):**
- **Knockout / rejection state:** semantic-error neutral treatment — `--semantic-error` #EF4444 family on `--semantic-error-50` #FEF2F2 background, matching the existing `rejeitado` badge in `DashboardCandidatoPage`/`MeuPerfilCandidatoPage`. The rejection message itself is **neutral/calm**, NOT alarmist red-on-red — use the muted/neutral surface with a single restrained error accent, consistent with the dignified-rejection tone (D-15).
- **Success / survivor:** `--semantic-success` #10B981 family OR brand-accent turquoise for the confirmation, consistent with existing `aguardando_resposta` positive treatment.

## Copywriting Contract

All copy is **pt-BR**. Product language: "avaliação comportamental/cognitiva" — **NEVER** "teste psicológico" (CLAUDE.md, LGPD-04). No field in this phase touches that vocabulary, but the rule holds for any helper text.

| Element | Copy |
|---------|------|
| Primary CTA (form submit) | **"Enviar candidatura"** (verb + noun; `Send` lucide icon; reuses the existing submit CTA pattern in `FormularioCandidaturaPage`) |
| Secondary nav (back) | **"Voltar"** (`ArrowLeft` icon — existing pattern) |
| Section heading — vaga | **"Resumo da vaga"** |
| Section heading — currículo | **"Seu currículo"** |
| Section heading — qualificação | **"Algumas perguntas sobre a vaga"** (neutral; deliberately gives NO hint that an option may be a knockout — D-06) |
| Field helper — data de nascimento | **"Usamos sua data de nascimento apenas para fins de cadastro. Ela nunca é usada para avaliar sua candidatura."** (LGPD-01 / D-05 transparency; age is structurally excluded from any decision) |
| Empty state heading (vaga sem perguntas) | *No empty-state UI* — a vaga without qualification questions simply renders the form without the qualification section (existing D-14 behavior in `FormularioCandidaturaPage`; no warning copy) |
| Empty state body | n/a (see above) |
| Error state (validation) | Inline per-field, pt-BR, from the Zod schema (existing pattern): e.g. **"Selecione uma opção"**, **"Campo obrigatório"**, **"Informe um valor válido"** |
| Error state (submit / network) | Existing error-code routing toast (sonner): **"Não foi possível enviar sua candidatura. Tente novamente em instantes."** (NETWORK_ERROR / DATABASE_ERROR) — keep the existing copy; do not expose internal codes |
| Error state (duplicada) | **"Você já se candidatou a esta vaga."** (DUPLICATE_APPLICATION — existing) |
| **Knockout rejection message (D-15 [LOCKED] — neutral, single, never exposes the criterion)** | **"Após análise dos requisitos da vaga, não seguiremos com sua candidatura neste momento."** |
| Knockout rejection — sub-line (dashboard context) | **"Agradecemos seu interesse na Beauty Smile."** (optional warm closer; never explains *why*; never offers "revisão por pessoa natural" — that is Phase 15) |
| Success / survivor confirmation heading | **"Candidatura enviada!"** |
| Success / survivor confirmation body | **"Recebemos sua candidatura. Em breve nossa equipe entrará em contato sobre os próximos passos."** |
| Dashboard label — rejeitado | **"Não selecionada"** (reuse existing `STATUS_CANDIDATURA_LABELS.rejeitado` — confirm wording stays neutral, NOT "Rejeitada" in candidate-facing copy if the label is harsh) |
| Destructive confirmation | **None.** This phase has **no candidate-initiated destructive action.** The knockout auto-rejection is server-side and synchronous (it is not a button the candidate presses), so there is no confirmation dialog. The candidate is shown the neutral result, not asked to confirm a deletion. |

> **Tone note (D-15):** The rejection surface must read as *dignified and calm*, not punitive. Use neutral/muted color, normal body weight, no red banner, no exclamation. The candidate must NOT be able to infer which answer triggered it (no "porque você respondeu X"). The criterion (`opcao_knockout_id`) is stored server-side for audit only and is never rendered.
