## Scenario 2: FLOW-CANDIDATURA (VAGA-03 + CAND-01..03) — Anon → redirect → submit

**Por que manual:** ESTE É O BUG PRIMÁRIO que motivou Phase 4.1. Phase 4 [04-08] UAT-J05 só verificou que o redirect query param era preservado, NÃO que o submit handler executava (silent return). Plan 04.1-03 commit 1534b45 substituiu o silent return por 3 toasts + disabled button. Este cenário reproduz exatamente o caminho que o milestone audit chamou de FLOW-CANDIDATURA broken.

**Passos:**

1. **Logout** se logado. DevTools → Application → Storage → "Clear site data".
2. Navegar para http://localhost:3003/vagas (anônimo).
3. Clicar em qualquer card de vaga ativa → aterrissa em `/vagas/<slug>`.
4. Clicar "Candidatar-se" (botão anon) → deve redirecionar para `/auth/login?redirect=/candidato/candidatura/formulario/<slug>` (verifique URL na barra).
5. Preencher: `fernando@beautysmile.com.br` + senha. Clicar "Entrar".
6. **Esperado pós-login:**
   - Toast verde: `Login realizado com sucesso!`
   - Navegação aterrissa em `/candidato/candidatura/formulario/<slug>` (NÃO `/candidato/perfil` nem `/vagas/...`).
   - Página renderiza com detalhes da vaga + perguntas formulário visíveis.
   - **Botão "Enviar candidatura" inicialmente disabled** (até hydration completar dentro de ~3s) OU enabled se hydration já completa quando renderiza.
   - Dentro de ~3-5s, botão fica enabled.
7. **Upload PDF CV** (< 5MB, qualquer PDF válido). Verifique preview com nome do arquivo + tamanho + botão remover.
8. Responder todas as perguntas obrigatórias.
9. Clicar "Enviar candidatura".

**Esperado pós-submit:**
- **Submit handler NÃO retorna silent** (este era o bug — antes: `if (!cvFile || !user || !candidato || !vaga) return` sem feedback). Agora: ou submit dispara, OU toast claro indica falta (CV / sessão / vaga).
- Toast confirmando candidatura criada (verde) OU "Você já se candidatou a esta vaga" se duplicate (info).
- Navegação para `/candidato/perfil` (no caso happy path) OU permanência em `/vagas/<slug>` (caso duplicate guard).
