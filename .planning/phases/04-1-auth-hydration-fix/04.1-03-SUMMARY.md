## Decisions Made

- **Decision:** Inlined disabled expression on the submit button instead of keeping `submitDisabled` local. **Rationale:** The acceptance criterion mandates literal `disabled={!candidato` in the file (visible defense-in-depth gate at the JSX call site, per Phase 4 carryover lesson [04-08]). Removing the now-unused local variable avoids duplication and `void submitDisabled` workarounds. Net effect: −1 LoC, same runtime behavior.
- **Decision:** FormularioCandidatura toast routing prioritizes `!candidato || !user` FIRST. **Rationale:** This is the ACTUAL bug being fixed (FLOW-CANDIDATURA — candidato=null after redirect-from-anon login). `!cvFile` is reachable in practice only via dev-tools (the button is also disabled when !cvFile, so the toast is defense-in-depth). `!vaga` is degenerate (route guard + slug roundtrip should prevent). Most-likely failure mode surfaces first; users see a helpful pt-BR message instead of the bug's silent-failure UX.
- **Decision:** RedefinirSenhaPage Pitfall 2 fallback also awaits hydration. **Rationale:** When `setNewPassword` fails with session_expired and tryAutoLogin recovers, a fresh signIn just completed — the same race window as the happy path applies. Skipping the fallback path would leave a known race window covered only by the listener's setTimeout(0) (Pattern 1) without page-level defense. Both branches now have the same guarantee.
- **Decision:** Preserved CadastroMultiStepForm `console.error('[CADASTRO] ...')` at line 448. **Rationale:** Cadastro is OUT of `PHASE_3_AUTH_PATHS` per pitfall7.grep.test.ts:39-46. Removing the log would lose useful debug context for cadastro errors with no Pitfall 7 benefit. Documented as decision so a future scan does not assume it was an oversight.
- **Decision:** Used the barrel import `@/features/auth/utils` (not the deep path `@/features/auth/utils/waitForCandidatoHydrated`). **Rationale:** Plan 02 SUMMARY explicitly documented the barrel re-export was added precisely so Plan 03 consumers could use the canonical short import path; matches the project convention for utility imports (`extractRole`, `rememberMeStorage`, etc., all imported via the barrel).
