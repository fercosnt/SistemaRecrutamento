## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| RH browser → configVagaService | Client UI collects config; all privileged writes route through the role-checked DEFINER RPCs (Plan 02). |
| client publishGate → server publish_vaga | Client gate is UX-only; the server RPC is the authoritative D-12 control. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-04-01 | Tampering | Publicar flow | mitigate | Client publishGate is instant UX only; publish_vaga RPC re-checks all 3 D-12 conditions server-side before status='ativa' (Plan 02). A bypassed client cannot activate an invalid vaga. |
| T-07-04-02 | Elevation of Privilege | tag save / config write | mitigate | All writes via configVagaService (anon client) → DEFINER RPC in-body role check + RLS (Plan 02). UI does not hold service_role. |
| T-07-04-03 | Information Disclosure | toasts/logs | mitigate | No PII/secrets in config toasts; reuse deduped sonner; no new console.* in RH path (Pitfall 7 invariant). |
| T-07-04-04 | Tampering | peso input | mitigate | Client tagOpcaoSchema .int().min(-999).max(100) + DB CHECK (Plan 02) — defense in depth. |
| T-07-04-05 | Tampering | non-rascunho publish no-op | mitigate | Publicar CTA gated on `status === 'rascunho'` client-side; publish_vaga RPC `WHERE status='rascunho'` is the server backstop (Pitfall 5 — 4 live status values). |
| T-07-04-SC | Tampering | npm installs | mitigate | No new packages; all shadcn primitives vendored (UI-SPEC Registry Safety = not applicable). |
</threat_model>
